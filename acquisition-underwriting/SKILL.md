**RULE EVIDENCE (v4.35, Gabriel in-turn 2026-10-23).** Every doctrine change entry (new rule, changed constant, new gate, new floor, new weight) carries one Rule Evidence line in `versions/CHANGELOG.md`. A rule without one is INCOMPLETE and is not merged.

| Field | Content |
|---|---|
| Evidence ID | `RE-<version>-<n>`, unique |
| Incidents | Count of INDEPENDENT deals or events that exposed the problem, each with date and deal. Two findings on one deal count once. |
| Expected loss | probability x severity, in $ per deal and per year, with the source of each factor; `[UNQUANTIFIED]` is allowed but must say what would quantify it |
| Evidence class | `ORA-OBSERVED` · `EXTERNAL-ANCHORED` (cited public benchmark) · `THEORY` (mechanism only) · `RATIFIED-JUDGMENT` (Gabriel's decision with no data yet) |
| Testable | The metric and dataset that will confirm or refute it (e.g., `BackTestDataset / Variance_Review line "Renewal rate"`) |
| Sunset review | Date; default the December back-test that follows the next 12 months of data |
| Ratifier / date | Who, when, and whether in-turn |

**Admission rule (ratified 2026-10-23):** a change to a floor, weight, constant or gate is admitted when it has **at least 2 independent incidents OR a quantified expected loss of at least 0.5% of median deal price per deal**. A **single-incident** rule is allowed when tagged `EVIDENCE: SINGLE-INCIDENT` and given a sunset at the next December back-test (it then gains a second incident or is reviewed for retirement). **Exempt from the count** (they still carry the field): legal and safety rules, data-integrity guards, wording or naming-only changes. **Gabriel's in-turn ratification is always sufficient**; the field then reads `RATIFIED-JUDGMENT`. At each December session the back-test dataset (`references/outcome-feedback-and-backtest.md`) records CONFIRMED / REFUTED / INCONCLUSIVE next to every Evidence ID whose Testable metric now has data.

## STAGE -1 — INTAKE RULES (v1.1-G; mandatory before any score is quoted)

**Read `references/doctrine-rationale-and-incidents.md` before disputing or extending any item below.**

1. **County-auditor year-built lookup** for every parcel (**Jefferson County KY / Louisville, v4.40:** PVA building data is paywalled and ORA does not subscribe — Gabriel 2026-10-29; use the Jefferson County Clerk deed search per deal for vintage and deed history, and the public LOJIC ArcGIS layers for zoning, form district, binding plans, flood and fire district) — the vintage ramp needs a real year; UNK defaults to 1995 (the ramp's oldest endpoint, a **65% discount floor**) and is flagged in QUESTIONS FOR GABRIEL. **District of Columbia (v4.61):** run `scripts/dc_parcel_pull.py --ssl "<SQUARE> <LOT>"` (or `--address`) as the first intake call. One query returns owner, last sale, current + proposed assessment (land/improvement), ten years of real-property bills with penalty, interest and fees, a late-payment count, CAMA year built / GBA. It covers Rules 1, 8 (assessment half) and 10. Flood stays with `ora-flood-zoning-dd`: the script queries FEMA only with `--flood` (a centroid pre-check, off by default; Gabriel 2026-11-24). A late payment in 2+ of the last 5 tax years scores as a Seller/Motivation signal (tax delinquency). The layer does NOT carry the BID tax, public-space fees or special assessments: confirm those on MyTax.DC (Tax History tab) and add them as OpEx lines. Never re-type tax history from screenshots (RE-4.61-1).
2. **Load-bearing rent/NOI verification:** the NOI figure must be verified against a source document (rent roll, lease, income statement) BEFORE any score is quoted. Basis + Yield share one denominator — 45 correlated points ride on it. Unverifiable → score carries [est] and blue-cell discipline; say so wherever the score appears.
3. **Dual-brokerage price conflict check (v3.4):** more than one active listing at different prices → halt Economics scoring (Basis and Yield) until the authorized listing agent and current ask are confirmed. 4. **Data Provenance & Conflict Register (v4.0):** any two sources disagreeing on a load-bearing field (year built, GBA/office SF, clear height, power, cranes, any material physical/vintage fact — not just price) → log it (field / OM value / CoStar value / county-auditor value / value used / basis for choice). Required on every FULL-mode memo (IC MEMO §3) when a conflict exists; never silently pick one source. Default: county-auditor wins on vintage/legal facts; on-site observation or a signed lease overrides an OM claim; state the basis in every row.
5. **Deal-decision-ledger precedent check (v4.2; SCREEN mode only, before scoring):** read `memory/deal-decision-ledger.md` in full; a candidate sharing geography, asset type, seller-motivation signal, or a named rule with a prior decided row is a precedent hit — cite matching rows by date + deal name in the output scorecard (Stage 2 block). ## STAGE 0 — GATES (Ruling 5: NO HARD KILLS — breaches are FLAGS, screened as exceptions; only Gabriel kills a deal)

A gate breach = prominent flag + screen/score as exception anyway; verdict label **GATE-FLAGGED** (never KILLED). Pure out-of-market junk gets flagged-and-deprioritized rather than scored in depth. **Institutional benchmark note (v4.3):** banks (OCC Handbook) hard-gate environmental, structural and zoning defects; Ruling 5's flag-not-kill is a **deliberate, correct divergence** that lets an all-cash generational-hold family office look at deals a bank must auto-reject — never let an "institutional hardening" pass walk it back.

1. **Product:** Class B/C industrial — shallow-bay multi-tenant, flex, office-warehouse, OR functional single-tenant ≤40,000 SF (scored EQUAL to multi-tenant). Quasi-IOS single-tenant <20K SF on land-heavy parcels = explicit target profile. Office % never kills if 1-story with adequate clear behind the finish (demo-able); ≤30% ideal.

## SCREEN PACKET (v4.59 — machine-readable handoff to the command-center engine)

**Final step of every SCREEN, UNDERWRITE and FULL run** (not SNAPSHOT or COMPS), after the verdict, floors and STAGE 2.5 are final: write one JSON file `<deal folder>/ScreenPacket_<Property>_<MMDDYYYY>.json` beside the underwrite workbook (SCREEN with no workbook: the same deal folder). `<Property>` and the date follow the deal-file naming schema (`[DocType]_[Property]_[MMDDYYYY]`); a same-day re-run overwrites its own packet, a later run writes a new dated file. Shape: `ora.acq-screen-packet/1`, read by `scripts/import-acq-screen-packet.ts` in the oxford-command-center repo and validated against the engine's `AcquisitionInput` contract. Field-by-field map: **`references/screen-packet.md`** (read it before writing a packet). The packet is how the screen reaches the engine's score and calibration record; without it the run is invisible to the command center.

Envelope: `schema` = `ora.acq-screen-packet/1` · `skillVersion` = `acquisition-underwriting v<X.Y> <MODE>` · `screenedAt` = run date `YYYY-MM-DD` (never a future date: the importer rejects one later than tomorrow UTC) · `deal` · `sourceFiles` (workbook, memo) · `input` · `notes`.

Rules (each one is a reject or a silent mis-score if broken):

1. **Blank beats inferred.** `input` carries only fields this run established from a cited source. Anything tagged DATA-GAP, unverified, or an estimate the run itself did not adopt is **omitted** (never `null`-padded, never guessed, never defaulted). The engine reads an omitted field as unknown and treats it conservatively (gate not confirmable, sub-score 0, verdict capped at T2) — the correct outcome for an unknown.
2. **Rates and shares are decimals:** `0.0743`, never `7.43`. The importer rejects a percent-form value; it never divides by 100. Applies to `stabilizedYoc`, `unleveredIrr10yr`, `leveredIrr`, `ust10yr`, `exitCapPct`, `officePct`, `vacantSfShareAtClose`, `envRemediationPctOfPrice` and every 0..1 score.
3. **One tested price.** `price` is the price the floors were tested at (ask, LOI or contract — say which in `notes.price`). `unleveredIrr10yr` is the 10-yr unlevered IRR at that price; `stabilizedYoc` and `allInBasis` are exactly what the STAGE 1 Yield and Basis floors used at that price. Never mix an ask-price IRR with an offer-price basis.
4. **`productType` = this run's own Gate 1 classification** (contract enum; alt-class such as multifamily = `other`), not the broker's label.
5. **`ddKnown`: `true` only when the STAGE 2.5 item is RESOLVED with a source** (FIRM panel, zoning letter, roof report, PCA). Unresolved = `false`.
6. **`notes` cite a source per populated field** (workbook cell or memo section, e.g. `Returns!B57`, `IC memo §6`), plus a mandatory `left-null` key naming every omitted field the engine reads and why. Where the engine's result will differ from the run's (e.g. IRR-floor add-ons the contract has no input for), say so in `notes.tieOutCaveat`.
