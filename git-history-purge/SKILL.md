# Git history purge (v2.4)

Run for real on two public repos: a config repo (2026-11-20: 313 branches + 1 tag rewritten, then 2026-11-24 local cleanup to 0 changed commits) and ora-skills (2026-11-23). Every step below either ran or was learned from a failure.

**Principle: the purge changes history, never main's current tree.** Scrub the tip first with a normal reviewed PR; the purge then only rewrites what is no longer visible.

**Principle: nothing else may write to the remote between the backup and the push.** The freeze (Step 0) makes that true; `leased_push.py` (Step 4) proves it before pushing and refuses otherwise. Neither is enough alone.

**Principle: pushes are unfrozen only when no local copy can carry old history back.** Step 6 moves every local checkout, whole, into the archive and re-clones the purged remote in its place, by hand from commands `inventory` prints, then proves the new clone with an object-level count, instead of relying on a pre-push hook. Step 6 deletes nothing.

**"Old history" means: reaches a commit the purge CHANGED or DROPPED.** Not "root commit is in the backup" (a clean first commit keeps its SHA, so new branches share it) and not "no merge-base with main" (an unrelated orphan branch has none either).

**Gates (Hard Invariant 1 class, irreversible):** Gabriel's in-turn yes before the force-push, before any repo-setting change (rulesets, branch protection), before the Step 6 moves, and before filing the Support request. Never change repo visibility or delete/recreate the repo to "fix" a purge; on ORA's six public repos visibility is ruled ("keep public, do not re-ask").

Scripts are stdlib Python in this skill's `scripts/` folder. Set `S` once to that folder: `~/.claude/skills/git-history-purge/scripts` when the skill is installed there, otherwise `<ora-skills checkout>/git-history-purge/scripts`. Call them as `python -I "$S/<script>"` from any directory. Each prints counts, plus ref names, paths and blob/commit ids with every configured value masked as `[private]`, never a value itself.

## Step 0 - inventory and freeze (before the backup)
- Remote: branch/tag count, fork count (`gh api repos/O/R --jq .forks_count`), PR count, default branch, branch protection and rulesets. Forks keep the data; say so.
- Ref namespaces: `git ls-remote <url>` with no pattern lists every ref the remote serves; count them by namespace (`git ls-remote <url> | cut -f2 | cut -d/ -f1-2 | sort | uniq -c`). This skill handles only `refs/heads`, `refs/tags` and GitHub's `refs/pull` (Steps 3-4 and 7). Anything else, such as `refs/notes/*` or a namespace a tool created, is never rewritten or pushed, so its data would stay on the remote, and `leased_push.py prepare` refuses a backup that holds one. Decide each now: the Step 1 mirror keeps a copy, then it is deleted on the remote (`git push <url> --delete <ref>`, its own yes) and a second backup is made for the purge.
- Local pushers: scheduled tasks (both fleets), CI that pushes, the live checkout and other sessions on it. Pause each via its supervised tool (`update_scheduled_task enabled:false`, never delete). Block the live checkout on every remote, not only `origin`. In the checkout, record the current push URLs first (Step 6 item 8 puts them back), freeze every remote, then check:
  ```bash
  mkdir -p <B>
  git config --get-regexp '^remote\..*\.pushurl$' > <B>/pushurls-before.txt
  git remote | while read r; do git config --replace-all "remote.$r.pushurl" DISABLED-history-purge-<date>; done
  git remote -v | grep '(push)$' | grep -v DISABLED || echo "every push URL is frozen"
  ```
  `--replace-all` matters: a remote with two push URLs keeps the second one live under a plain `git config`. Any `(push)` line printed instead of "every push URL is frozen" is still live; freeze it before going on.
- Local copies: every clone of this remote on the machine (dirty-tree-triage's clone discovery groups clones by `origin` URL), plus the live checkout's worktrees. Each needs Step 6.
- Remote lock (repo-setting change, its own yes): a temporary ruleset on all branches and tags restricting creation, update and deletion, with bypass for the repository admin role only. It stops every other account, app and bot, not pushes made with the owner's own credentials (covered by the local freeze and Step 4). Remove it after Step 5.

## Step 1 - backup outside every repo
`git clone --mirror <url> <B>/mirror.git`, `git bundle create <B>/all.bundle --all`, `git bundle verify`. `<B>` = `C:/Users/Owner/_archive/<repo>-prepurge-<date>/`. The backup holds the private data: local only, never pushed. **Never fetch into it afterwards**: it is the record of the old commits. If you need a newer copy (Step 4 exit 3), make a second backup directory.

## Step 2 - build rules from what is actually present
- Private values go in a config file OUTSIDE every repo (`~/.ora-private/purge/`). Never type them into a command, commit message, PR, chat or log. Set `"tip_ref"` if the default branch is not `refs/heads/main` (the scan refuses a missing one). Known phone numbers go in `"phone_numbers"` (10 digits): every written form is covered, including compact `6145550123`.
- Run `python -I "$S/purge_scan.py" scan <B>/mirror.git <config.json> <rules.txt>`. It checks every path a file was ever stored at, plus commit and tag messages, and writes a rule only for values present, in each written form (`123,457`, `123457`, `9,876.54`, `123,456.5`, negatives as `-123,457` or `(123,457)`). Rules are anchored so hashes, longer numbers and longer digit runs are untouched. Any rule that matches the tip is dropped (it would change the tip's tree). Report counts, never values or "masked samples".
- `scan` and `verify` read notes refs (`refs/notes/*`) wherever present, like branches: their note blobs, commit messages and ref names; both print `notes refs read: <n>`.
- Read the `values skipped ... NOT searched` count: round thousands, whole numbers below `min_integer` (default 10000) and non-whole values below 1,000 are not searched, because replacing them would hit unrelated text. If one must go, remove its file by path or add an exact literal.
- A dropped rule means the value is still live at the tip: scrub it by PR first, or accept it stays.
- `literals found in file names` > 0: text rules never rename paths. Remove those paths with `--path-regex`/`--invert-paths`, or rename them.
- Work email in authors: GitHub REJECTS pushes of commits carrying a private email ("push declined due to email privacy restrictions"). Plan the mailmap now (`Name <ID+login@users.noreply.github.com> <work@email>`; ID = `gh api user --jq .id`).
- The rules rewrite text only (by content, as filter-repo decides). Binary files that hold the data (PDF, XLSX, images) must be removed by path in Step 3; find them with `git filter-repo --analyze` on a scratch copy. Verify searches binary blobs as raw bytes and also inside what it can decode: every member of a zip container (xlsx, docx, pptx, zip, plus a zip or PDF inside one, one level deep), each member again with its XML tags removed (a figure Word split across runs), the member names, UTF-16 text (with or without a byte-order mark), and a PDF's FlateDecode and unfiltered streams, each decoded stream read again the same way (an attached xlsx is opened), plus the text of its literal and hex strings, each on its own and with TJ array pieces joined. A value found there fails Step 3. Verify cannot see inside an encrypted zip member or PDF, a zip member or PDF stream under another compression or filter (such as images in a PDF), PDF text drawn with a font's own glyph codes (Identity-H/V, common in PDFs exported from Word), a container nested more than one level deep, an image file, a gzip/bzip2/xz/7z/rar archive or a legacy Office (OLE2) file. It lists each such blob at the end as `OPAQUE <blob> path=<path> commit=<commit> ref=<ref> reason=<why>`, where `ref` is the full name of a branch, tag or notes ref that reaches that commit. For a blob a tag points at directly, or holds in a tree it points at, `commit` is `(none)` and `ref` is that tag (with `path` its path in that tree, or `(none)`). For a blob held only by a note, `ref` is the notes ref and `path` is the id of the annotated commit. `path=(none) commit=(unreachable) ref=(none)` means no branch, tag or notes ref reaches the blob, yet it is still in this repository: it is dangling, or only a reflog, a stash or a ref outside those namespaces (such as `refs/pull/*`) holds it. Pushing branches and tags does not send it, but a ref outside them can still publish it. Run `git log --all --reflog --source --find-object=<blob> --format="%H %S"` to see what holds it (no output means it is dangling), then check it like any other OPAQUE blob. OPAQUE does not change the exit code: open each one and check it, or remove it by path and redo Step 3 from a new `prepare`.

## Step 3 - rewrite a fresh copy, then prove it
```bash
python -I "$S/leased_push.py" prepare <B>/mirror.git <B>/work.git
git -C <B>/work.git filter-repo --force --invert-paths --path-regex '<removed-paths>' \
  --replace-text <rules.txt> --replace-message <rules.txt> --mailmap <mailmap.txt>
```
`prepare` makes a fresh copy holding only the backup's branches and tags (no `refs/pull/*`: those are never pushed, and GitHub Support handles them in Step 7) and records the backup's refs in `work.git/purge-backup-refs.txt`; it refuses an existing `work.git` (move it aside, never delete). `prepare` also refuses (exit 2, nothing copied) a backup holding any ref outside `refs/heads`, `refs/tags` and `refs/pull`, and prints each as `OTHER-NAMESPACE <ref>`: nothing in Steps 3-5 rewrites or pushes those refs, so their data would stay on the remote while every check passes. Delete each on the remote (its own yes), make a NEW backup directory (Step 1, e.g. `<B>/mirror2.git`), run Steps 2-3 from it, and keep the first backup: it is the only copy of what was deleted. A further filter-repo pass on the same copy is fine. filter-repo drops the `origin` remote; push by URL. Then all must hold, else stop:
- `git -C <B>/work.git rev-parse <default-branch>^{tree}` equals the backup's.
- `python -I "$S/purge_scan.py" verify <B>/work.git <config> <rules.txt>` exits 0. Besides re-applying the rules, verify searches EVERY object in the store (text blobs, binary blobs, file names in trees, commits and tags) for every configured value, phone and literal, independent of the rules. Values in the tip's files are reported as kept at the tip (accepted). A remaining value is either a scan miss (add an exact literal or a path removal, redo Step 3 from a new `prepare`) or a different number that contains it (e.g. `1,123,457`); confirm with `git -C <B>/work.git grep` locally, and proceed past a confirmed false alarm only with Gabriel's yes. filter-repo rewrites contents, never ref names. If verify prints `REF-NAME <ref>` (the value shown as `[private]`), a branch or tag name holds a configured value or matches a rule, and verify exits 1. Rename it in `<B>/work.git` before the push. A branch: `git -C <B>/work.git branch -m <old> <new>`. A tag: never put a lightweight tag on the old one, because the old tag object still holds the old name (verify keeps failing and the push would publish it). Make a new annotated tag on the peeled commit and drop the old object:
  ```bash
  git -C <B>/work.git tag -l --format='%(contents)' <old> > <B>/tagmsg.txt
  git -C <B>/work.git tag -a <new> -F <B>/tagmsg.txt '<old>^{}'
  git -C <B>/work.git tag -d <old>
  git -C <B>/work.git reflog expire --expire=now --all
  git -C <B>/work.git gc --prune=now
  ```
  then re-run verify. The tagger and date become yours, and a signed tag loses its signature (for a lightweight old tag, `tag <new> <old>` then `tag -d <old>` is enough). Step 4 then lists the old name as `DELETED-BY-REWRITE` (exit 4): confirm it and re-run with `--delete-removed`.
- `git -C <B>/work.git log --all --format='%ae%n%ce' | grep -ci <work-domain>` is 0.
- Ref count equals the backup's branches and tags, minus refs the rewrite deleted (Step 4 lists them).

## Step 4 - checked, leased push (after Gabriel's yes)
- Protected default branch or a ruleset that blocks force-push: loosening it is a repo-setting change (its own yes); restore it right after.
- `python -I "$S/leased_push.py" <B>/mirror.git <B>/work.git <url> --dry-run`, then without `--dry-run`. Before pushing anything it checks the chain: the backup still matches the refs recorded at `prepare`, every ref was rewritten from the backup's SHA, and the remote still has the backup's SHA. Every lease is against the backup, never against what the remote shows at push time. Batches of 40; the default branch (read from the remote's `HEAD`; `--main-ref` must agree) is pushed alone, last, and only if nothing else was rejected.
- Exit 2: bad path or URL, a copy not made with `prepare`, `STALE` (the backup changed after the copy), or a default branch that cannot be determined or disagrees. Redo Step 3 from a new `prepare`.
- Exit 3: `MOVED` refs (someone pushed after the backup, including a brand-new branch or tag). Printed before the push, nothing was pushed. Printed after it ('the remote moved DURING the push'), it can also name refs an earlier run already pushed; the refs pushed stand and the recovery is the same. Find who (the freeze leaked). Make a NEW backup directory from the remote (Step 1), redo Steps 2-3 from it, and keep both backups for Step 6.
- Exit 4: `DELETED-BY-REWRITE` refs (every commit on them was purged, per the refs recorded at `prepare`) still hold the data on the remote; nothing was pushed. Confirm the list, then run again with `--delete-removed`.
- Exit 1: a partial push, including a deletion the remote refused (`REJECTED` on a `--delete-removed` ref). Read each `REJECTED` / `HELD` line, fix the cause, run again as-is: refs already pushed are skipped, and anything that moved meanwhile stops the run (exit 3) instead of being overwritten. Never re-clone or `prepare` again to "refresh" after a partial push: the backup and the copy are the baseline the leases depend on.
- Hand-rolling it: `--force-with-lease=<ref>:<backup-sha>` and a refspec WITHOUT `+`. A `+<ref>:<ref>` refspec forces past its own lease. Never bare `--force`, `--prune` or `--mirror` (it hits `refs/pull/*`).

## Step 5 - verify from a fresh clone
`git clone --bare <url> <B>/verify.git` and re-run Step 3's checks there. `git clone --bare` fetches only branches and tags, so also run `git ls-remote <url>` with no pattern: any ref outside `refs/heads`, `refs/tags` and `refs/pull` fails Step 5. A local check of `work.git` proves nothing about GitHub. Use `--bare`, not `--mirror`: a mirror clone also fetches GitHub's `refs/pull/*`, which still hold the old history until Step 7. Then remove the Step 0 ruleset.

## Step 6 - local copies: archive intact, re-clone by hand, then unfreeze
Do this for the live checkout and for every other local clone from Step 0. Each clone needs its own Step 6; for example, a second clone kept in an `archive/` folder goes through the whole procedure separately. Pushes stay frozen until it passes. Nothing is deleted. The old checkout moves into the archive whole, with every worktree, reflog, stash entry, unreachable object, submodule repository, ignored file, config and hook. A fresh clone of the purged remote takes its place, and only kept work is fetched across from the archived copy. Old history then exists only in the archive. `local_cleanup.py` moves nothing: `inventory` is read-only and prints the commands, and you run them.

The procedure covers ONE layout:
- the main worktree, on a branch that has commits or detached; it may be OLD (the new clone is then detached at the clone's HEAD);
- linked worktrees that are direct folders, none inside the main folder or inside another worktree;
- KEPT worktrees that are clean, on a branch with commits or detached at a commit a carried ref reaches, with no initialised submodule and no per-worktree ref;
- kept local branches, tags, notes, other refs and stash entries (a stash entry that holds a purged object counts as OLD and stays in the archive);
- ignored files, which are named exactly and never carried (item 5).

`inventory` refuses everything else (exit 2, a `REFUSED` line each, with its fix). Do the fix by hand, then run `inventory` again:

| REFUSED | By hand |
|---|---|
| unborn branch (no commit yet), any worktree | `git commit --allow-empty -m start` there, or switch it to a branch with commits |
| worktree nested inside the main folder or another worktree | `git worktree move -f -f <path> <new path outside every worktree>` (a lock and its reason stay) |
| main checkout inside a linked worktree | `mv <main> <new path outside every worktree>`, then `git worktree repair` in the moved folder; run `inventory` on the new path |
| initialised submodule in a KEPT worktree | in each: push every commit, commit or drop every change; then `git submodule deinit -f <sub>` (its repository moves to the archive); after Step 6, `git submodule update --init` in the new clone |
| per-worktree ref (`refs/worktree/*`, `refs/bisect/*`, `refs/rewritten/*`) in a KEPT worktree | in that worktree: `git branch <name> <ref>`, then `git update-ref -d <ref>` |
| KEPT worktree detached at a commit no carried ref reaches | `git branch <name>` in that worktree |
| carried ref (branch, tag, notes or other) that reaches a purged blob, tree or tag object | re-point it as in item 0b, or rebuild it without that content (`git update-ref <ref> <new> <old>`); the old tip stays in its reflog in the archive |
| modified, untracked or staged-only files in a KEPT worktree | the owning session commits, stashes or pushes (dirty-tree-triage when the owner is unclear) |
| skip-worktree / assume-unchanged files that differ from the index | two commands per file, `git update-index --no-skip-worktree <file>`, then `git update-index --no-assume-unchanged <file>`; then commit or `git stash` |
| operation in progress, any worktree | `git <op> --continue` or `--abort`, `git bisect reset` |
| worktree folder missing | restore the folder, or `git worktree prune` |

0a. `python -I "$S/local_cleanup.py" changed <B>/verify.git <B>/mirror.git [<B2>/mirror.git ...] --out <B>/old-commits.txt` records every commit the purge changed or dropped, plus `old-commits.txt.objects` (exit 1 if none: stop and find out why; that file then holds only a `0 commits` marker, the one empty form `inventory` accepts; an empty or malformed old-commits file is refused with exit 2).
0b. Old refs are not carried across; they stay only in the archive. A branch on old history whose work must stay usable is re-pointed onto its REWRITTEN counterpart first (it then counts as kept), never onto a commit made from its own old tree (that keeps the purged blobs, and `inventory` refuses it). Pin the old tip as a SHA so the compare-and-swap can fail: `OLD=$(git rev-parse refs/heads/<branch>)`, `git fetch <B>/verify.git refs/heads/<branch>`, `git update-ref refs/heads/<branch> "$(git rev-parse FETCH_HEAD)" "$OLD"`. The old tip, and any local commits the remote never had, stay in the branch's reflog in the archive. A local-only branch has no counterpart: rebuild its own changes onto `<new-main>` by hand; `inventory` confirms it holds no purged object. In `~/.claude` this is a governance write: config-write token with Gabriel's quoted words.

1. Stop everything that uses the checkout or any of its worktrees: every session, IDE, editor, terminal and scheduled job, and git's fsmonitor daemon (`git -C <repo> fsmonitor--daemon stop`). For ora-skills that includes the Windows scheduled task "ORA Skill Cache Capture" (`Disable-ScheduledTask -TaskName 'ORA Skill Cache Capture'`). Work from a folder outside the checkout.
2. `python -I "$S/local_cleanup.py" inventory <repo> <B>/old-commits.txt --out <B>/inv.json --archive <B>/rehome-<n> [--clone-url <purged-url>] | tee <B>/inventory-<n>.txt`. `<repo>` is the main worktree's top folder. `<B>/rehome-<n>` must not exist yet, must be outside every worktree, and must be on the same volume (on another volume a move copies). `--clone-url` defaults to `remote.origin.url` and must be the purged remote, never the backup or this checkout. The command prints every worktree, every local ref in every namespace and each stash entry as OLD or KEPT, plus the remotes, `core.hooksPath` and each worktree's ignored paths (`ignored, NOT carried`). Exit 2: do what each `REFUSED` line says (the table above), then run it again. Exit 0: the Step 6 commands follow, between `# --- Step 6 commands (printed, not run) ---` and `# --- Undo ---`, then the undo up to `# --- end ---`. After Gabriel's yes, run them in order, as printed. Every line must exit 0; if one fails, stop and Undo.
3. The `# 6.3` lines move every linked worktree to `<B>/rehome-<n>/worktrees/<k>-<name>/` and the main folder to `<B>/rehome-<n>/repo/` (Explorer works too; never delete), then run `git worktree repair` in the archived copy so its worktrees open there. A move that fails on Windows means a process still holds the folder: find and stop it. The archived copy keeps its own pushurls frozen. When `core.hooksPath` was an absolute path inside the checkout (`install_hooks.py` sets `<repo>/.git/ora-hooks`), a printed line points the archive's `core.hooksPath` at `<B>/rehome-<n>/repo/.git/ora-hooks`; without it, the archive would run the NEW clone's hooks. A submodule inside an archived worktree may not open in place, because its `.git` file holds a relative path. Its repository is kept whole under `repo/.git/[worktrees/<id>/]modules/`, and Undo puts it back.
4. The `# 6.4` lines clone the purged remote and bring the kept work across, in this order:
   - `git clone --no-local --no-checkout <url> <repo>` (`--no-local` matters only for a remote that is a local path: without it git copies the whole object store, unreachable old objects included);
   - add the checkout's other remotes;
   - freeze every push URL (`config --replace-all remote.<r>.pushurl DISABLED-history-purge`);
   - fetch each kept branch, tag, notes or other ref from the archived copy, one per line (`fetch --no-tags --update-head-ok <archive>/repo +<ref>:<ref>`). Remote-tracking and old refs are never fetched, and `--no-tags` keeps an old tag on a kept commit out;
   - fetch each kept stash entry by SHA, then `stash store -m <msg> <sha>` it, oldest first, so the order is the same;
   - check the main worktree out: its branch; detached when it was detached; detached at the clone's HEAD when it was OLD;
   - set the kept branches' upstream config;
   - `worktree add` each kept linked worktree at its path (detached if it was), and `worktree lock --reason <reason>` it if it was locked.
5. Ignored files: copy back from `<B>/rehome-<n>/repo/` (and each archived worktree) only the paths `inventory` named that the repo's tools need, one at a time. In ora-skills that is `_staging/` and `tools/real-identifiers.local.json`. Without `_staging/` (`PENDING_REIMPORT.md`, `STORE_AHEAD_OF_REPO.md`), `pending_reimport.py` reports "none pending" and a pending re-import is silently lost. Never copy a `.git` file or a worktree folder back, nor a folder holding one such as `.claude/worktrees/`: the new clone's worktree would then point at the archive. Copy, never move, so the archive stays complete.
6. Run the repo's hook installer on the new clone before anything else happens there (ora-skills: `python tools/install_hooks.py`). Until it runs, the new clone has no hooks. A v1.0 chained `old_history_guard.py` belongs only to the archived copy; do not re-add it. The old hooks and any `pre-push.bak-<stamp>` backups are in `<B>/rehome-<n>/repo/.git/ora-hooks/`. Answer a `hook_pin_check` re-pin prompt only on the new clone.
7. `python -I "$S/local_cleanup.py" overlap <repo> <B>/old-commits.txt` must exit 0 (0 old commits and objects). Then `python -I "$S/purge_scan.py" verify <repo> <config> <rules.txt>` must exit 0: `overlap` counts old objects by SHA, so a new commit that re-adds old content passes `overlap` but not `verify`.
8. Unfreeze, in the new clone (`cd <repo>`): remove every frozen value, then put back exactly the values recorded in Step 0:
   ```bash
   git remote | while read r; do git config --unset-all "remote.$r.pushurl"; done
   while read -r key value; do git config --add "$key" "$value"; done < <B>/pushurls-before.txt
   git remote -v
   ```
   Then resume the stopped sessions and re-enable the paused tasks (`Enable-ScheduledTask -TaskName 'ORA Skill Cache Capture'`; re-date each `[MODEL:]` tag). Confirm that the first scheduled push lands, then re-run the Step 5 verify once more.

**Undo** (any time before anyone works in the new clone): run the printed lines after `# --- Undo ---`. They move the new clone and its worktrees aside into `<B>/rehome-<n>/new-clone-aside/`, move every archived folder back to its path, run `git worktree repair` in the restored main checkout with every linked worktree path, and put `core.hooksPath` back when step 3 changed it. Skip a move whose source does not exist (a step that never ran). Pushes stay frozen.

## Step 7 - what a force-push cannot reach
`refs/pull/*`, cached commit/diff views and direct SHA URLs still serve old content. Only GitHub Support can purge them (help.github.com > Support tickets, logged in as the owner; the ticket page is `/ticket/personal/0/<n>`). Use category Repositories > Repository features (NOT "Deletes", which is the delete-a-repository flow). Include: the repo URL, the PR count, the "First Changed Commit" from `<B>/work.git/filter-repo/first-changed-commits`, orphaned LFS objects (or "none"), and that no secrets are among the removed data (or which were rotated). Never paste removed data. Count progress with `git ls-remote <url> 'refs/pull/*/head'` against the backup. After Support confirms, open one old PR's "Files changed" and check a removed path is gone. Mirrors, forks and past clones cannot be recalled.

## Step 8 - record
Event-log entry via `append-event-log.py` (counts, SHAs, backup and archive paths, residuals, ticket number), with Gabriel's quoted decisions.

## Common mistakes
| Mistake | Fix |
|---|---|
| `git push --force --prune` or `--mirror` | `leased_push.py`; `--mirror` touches `refs/pull/*`, `--prune` deletes refs |
| `--force-with-lease=<ref>:<sha> +<ref>:<ref>` | The `+` overrides the lease; drop it |
| Lease read from `git ls-remote` at push time | Lease against the backup; a post-backup push otherwise vanishes |
| Fetching a moved ref into the backup | Never; make a second backup and pass both to `local_cleanup.py changed` |
| Hand-made `work.git` | `leased_push.py prepare`; push refuses a copy without its ref record |
| Re-cloning the backup after a partial push | Rerun as-is; the backup and copy are the baseline the leases depend on |
| Rules built from a guessed value list | `purge_scan.py scan` writes only rules for values present |
| A rule that matches the tip | Dropped by the scan; scrub the tip by PR first |
| Unfreezing with old-history refs or worktrees around | Step 6 (`overlap` 0) and `verify` first; a pre-push hook is not a substitute |
| "Old" = root commit in the backup, or no merge-base with main | "Old" = reaches a changed or dropped commit (`local_cleanup.py changed`) |
| Cleaning old history out of a live checkout in place (reflog edits, `gc`, `worktree remove`, `stash drop`) | Step 6: the old checkout moves into the archive whole; every in-place attempt lost user data |
| Running Step 6 while a session, IDE or scheduled job uses the checkout | Stop them all first (item 1), including the ORA Skill Cache Capture task for ora-skills |
| Re-cloning from the backup or the archive | Clone the purged remote; only kept refs come from the archived copy |
| Copying an ignored folder back whole (`.claude/`, `.claude/worktrees/`) | Copy only the named files `inventory` lists; a copied `.git` file ties the new clone's worktree to the archive |
| Re-pointing an old branch onto a commit made from its own tree | Re-point it onto its rewritten counterpart (Step 6 item 0b); the old tree still holds the purged blobs |
| Deleting the archive once the new clone works | Never; it is the only copy of old refs, reflogs, stashes and ignored files |
| Freezing or unfreezing with a plain `git config remote.$r.pushurl` / `--unset` | `--replace-all` to freeze, `--unset-all` and the recorded `pushurls-before.txt` to unfreeze (Step 0, Step 6 item 8) |
| Verifying from a `--mirror` clone | `--bare`: a mirror fetches `refs/pull/*` with the old history |
| `rm -rf` of a work, verify or worktree folder | Move it into `<B>/`; never delete |
| Calling it done after the push | Fresh-clone verify, every local copy through Step 6 and verified, Support ticket, old-PR spot check |
