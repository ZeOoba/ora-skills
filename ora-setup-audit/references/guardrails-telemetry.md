## Rarity is neutral

- **Rarity is neutral, not evidence of bloat.** **Per-skill invocation telemetry DOES exist and you should use it — corrected 2026-09-06 (R23-10), after this clause said the opposite for 13 revisions while contradicting itself in its own next sentence.** `~/.claude.json#skillUsage` holds real `usageCount` + `lastUsedAt` per skill (115 name-variants / 1,011 logged invocations as of Revision 23; Revision 9 used it on 2026-08-14 to produce findings, one day after this clause claimed it did not exist). **Its three real limits, none of which is "it doesn't exist":** (1) CC/MCP surface ONLY — a skill that runs solely via Cowork/LAMS reads zero, so a zero means "not invoked from Code," never "unused"; (2) **no time window** — counts are cumulative from an unrecorded start, so a total cannot be turned into a rate; (3) **split namespaces** — the same skill is counted separately under bare and plugin-qualified names, **20 such pairs at Revision 23** (up from 6 at Revision 9; `docx` spans four), so **always merge on the segment after the last colon before ranking** or you undercount by up to ~65%. Rank by `words × merged count` when you want realized cost, not by size alone. `claude-markdown-health-check`'s Phase 7 JSONL signal (`~/.claude/projects/**/*.jsonl`) is structurally CC/MCP-surface-only in exactly the same way (sampled 25 CC + 25 LAMS sessions: 14/25 CC sessions had a matching transcript file, 0/25 LAMS sessions did — LAMS/Cowork tasks execute in a separate VM/cloud sandbox whose transcripts never sync locally). Treat the two as the SAME blind spot restated, never as independent or corroborating signals. So: **use the counts, and state their surface** — but never let a count alone carry a prune verdict. A prune verdict still needs corroborating evidence (CLAUDE.md references, event_log/memory mentions, task-folder presence on either fleet registry, explicit supersession language in another skill's own description), and you must state what was checked and came back empty so the absence is verifiable rather than asserted. **Revision 23 ran exactly that method over 50 zero- and low-usage skills and returned ZERO delete-candidates** — six of the zeros were zero because Gabriel had already unpublished them, and two (`annual-cycle`, `deal-retirement`) are read BY REPO FILE PATH from live scheduled tasks *precisely because* they are no longer name-invocable, so deleting their directories would break two running tasks silently. Expect that shape again. The question is never "how often does this run" — it's "is there still a reason this needs to exist."

## MCP connector, plugin and Extension verdicts: the five checks (v1.17)

Full text of the `SKILL.md` Guardrails bullet; content from the 2026-09-30 audit-workflow patch blocks.

Two Code-side errors on 2026-09-30 came from treating `skillUsage` and CC transcripts as usage evidence for MCP servers: Desktop Commander read as unused while it had ~19,300 recorded calls and 23 live specs. Before any delete or disable verdict on an MCP connector, plugin or Extension, run all five and state each result, including empty:

1. `usage_ledger.py summary` windows for the server (state `earliest_session_mtime`; LAMS logs cover ~2 weeks, so an empty window is weak evidence).
2. Server-own counters where they exist (DC `config.json#usageStats`; `tool-history.jsonl` covers ~7 days only, so the ledger's `dc` snapshots are the durable record).
3. Spec references: grep `mcp__<Server>__` and the server name across BOTH fleets' SKILL.md folders, plus registry enabled state. A reference in a disabled task implies nothing (1 of 29 LAMS tasks was enabled on 2026-09-30).
4. Non-replaceability: can native Cowork tools, `device_bash` or another connector do the job? (DC is the only Cowork path to Windows paths and the local network.)
5. A named non-DC fallback, or none.

Any server where checks 2-4 show use or non-replaceability is HOLD, not delete. `delete` requires all five empty AND a Gabriel ask; this skill never executes removals. Standing dependency: no Cowork-native read path to Windows-side files exists without DC; any audit proposing DC removal must show that path replaced first.

Cowork logs Notion, ms365 and HubSpot under connector UUIDs; `usage_ledger.py` maps them (`ALIASES`). Plugin roll-up rule: a roll-up of bundled-skill findings can only raise a plugin's verdict; report the most-protective of skill roll-up, per-server five-check result, and agent/hook references.
