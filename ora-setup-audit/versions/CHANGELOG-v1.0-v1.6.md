# ora-setup-audit — Changelog (v1.0–v1.6)

Archived from `SKILL.md` 2026-09-07 (retention rule adopted this same pass: at most 6
versions stay inline; adding v1.12 pushed the section to 13 entries, so v1.6 and older
were extracted together in one close-out). Repo-only — excluded from packaging per
`tools/package_skills.py`'s top-level `versions/` exclusion. This file opens the range;
subsequent extractions append here and rename it to its full range on close-out.

- **v1.6 (2026-08-22): corrected 3 un-pathed file references in Thread 1 that led a live audit pass to guess wrong.** Revision 18's Thread 1 assumed `blocklist.json` and `confidential-repos.json` lived under `hooks/` (no path was ever specified here) and had to discover the real locations (`plugins/blocklist.json`, repo-root `confidential-repos.json`) before it could check them; `mcp-needs-auth-cache.json`'s path was equally unstated. All three now carry their verified location inline. Doc-only; no thread logic changed.

- **v1.5 (2026-08-16): the local-mirror-drift bug class this skill kept finding (R10-1, recurred as R13-2) is now structurally prevented, not just detected.** Step 0's self-check and `setup-self-audit.py`'s `check_skill_mirror_drift()` both only ever DETECTED drift after the fact — neither could fix it, and a guard living inside the file it guards is structurally unable to fire when that file is the stale one. `tools/sync_local_skills_mirror.py` (new, in `ora-skills`, wired into `tools/hooks/post-commit` alongside the existing `pending_reimport.py` call) closes the gap at the source: every commit that touches a skill with an existing local mirror under `~/.claude/skills/` re-syncs it automatically, non-blocking, update-in-place only. Step 0 and the drift check both stay in place as a second line of defense (e.g. for a mirror created by hand outside a commit), but the routine case — repo edited, committed, mirror silently left behind — no longer needs either to catch it. 6 new tests: `tools/test_sync_local_skills_mirror.py`.

- **v1.4 (2026-08-15): added Step 0, a self-check for a stale loaded copy.** Revision 10 — the FIRST unattended run of this skill — resolved to the local `~/.claude/skills/ora-setup-audit/SKILL.md` mirror at v1.2, missing the v1.3 rev-band cap this very changelog entry's predecessor had added that same morning; nothing in the skill itself could have detected it was running stale. Step 0 has the running instance compare its own version tag against the canonical repo copy's before doing anything else, and say so in the published rev-band if they differ. Companion fix, same day: `setup-self-audit.py`'s new `check_skill_mirror_drift()` (Automation Audit R10-1) catches the same defect class independently, byte-for-byte, without needing this skill to run first — cited in Non-goals.

- **v1.3 (2026-08-14): closed the audit's own self-referential bloat gap.** Revision 8 (the first real invocation of this skill) found the artifact this skill produces had grown a full rev-band every revision since Revision 1 with no cap — the same unbounded-growth pattern Revision 7 flagged as the single largest finding in the System Schematic. Added Step 4a: a mandatory 4-entry rev-band cap with rollover to a companion `ora-automation-audit-history.md`, plus a durable working-copy file (`~/.claude/artifacts/ora-automation-audit.html`) mirroring the Schematic's DURABLE SOURCE pattern, so future revisions don't have to WebFetch the full published artifact to continue it. Not yet applied to the current artifact's 4 existing rev-bands (Revisions 5–8) since 4 is exactly at the cap — the mechanism takes effect starting Revision 9.

- **v1.2 (2026-08-13): renamed `claude-setup-audit` -> `ora-setup-audit`.** The platform refuses to install a skill whose name contains "claude" — the packaged `claude-setup-audit.skill` was rejected at the Save-skill click, not at packaging (`package_skills.py` exited 0 and validated frontmatter cleanly, so this constraint is enforced only at import). Renamed via `git mv` at file level; the directory-level `git mv` hit `Permission denied` on Windows. Only reference anywhere in the repo was its own frontmatter `name:` field, so the rename is self-contained; the H1 changed to "ORA Setup Audit" while every in-body mention of Claude Code/Cowork stayed, since the constraint is on the name, not the content. **Name-collision note:** `ora-setup-audit` was also the name of the retired June scheduled task cited in v1.1 below — a deliberate reuse (ratified 2026-08-13), so a future reader hitting `ora-setup-audit` in `event_log.md` should date-check before assuming which artifact is meant. The skill was never installed under the old name (no runtime cache dir ever existed), so there is no orphaned shadow copy to clean up.
