- v1.21 (2026-08-17: pre-flight frontmatter gate + the stale-mirror clobber it exposed). New step 2a. A `description` over 1024 chars, or a frontmatter `name` not matching its directory, makes the importer reject the `.skill` with **no error text anywhere** — no toast, no log line, no non-zero exit; the Save-skill click is a no-op. `tools/package_skills.py` has always caught both, which is why this had never been seen: every prior package went through the host packager. The gap is the paths where it cannot run — cloud Cowork sessions with no DC bridge, hand-built `_staging` packages, any `.skill` built without the repo. Found live 2026-08-17 authoring `listing-agreement-qc` v1.0 cloud-side: description 1220/1024, silent rejection, two build cycles lost. **The same session then hit a worse failure and it is the reason for step 2a's closing paragraph.** Lacking the repo, it based a package-and-stage-skill edit on `~/.claude/skills/synced/package-and-stage-skill/SKILL.md` — the platform mirror, which was still serving **v1.19** because the repo's own v1.20 (2026-08-16 size fix) had never been re-imported. The result was installed to the platform as a second, conflicting "v1.20" that silently reverted the size fix and grew the file ~4.7KB, on the skill the Automation Audit had just flagged as the largest and fastest-growing of the three measured. Caught only because a post-hoc repo check ran; the repo itself was never written, so no repo damage occurred. Two standing consequences: the synced mirror is NEVER an editing basis (it shows the last *imported* version, not the current one), and a version number is not evidence of currency — compare content hashes against the repo before building on anything.
