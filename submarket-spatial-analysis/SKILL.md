# Submarket Spatial Analysis (v1.9)

Analyze ORA properties and acquisition candidates against spatial demand drivers: highway access, intermodal proximity, last-mile geography, employment, and demographics.

## Scope

Covers all ORA target markets (OH, MD, IN, WI, MO, KS, TN) and submarkets within them. Used for acquisition screening, tenant-mix optimization, and disposition evaluation.

## Triggers

Acquisition candidate location scoring, submarket comparison, intermodal proximity check, drive-time analysis, demographic profile, ring demographics, employment growth check, last-mile suitability scoring, CoStar report ingest (submarket vs. peer-set read, nearby pipeline, rent basis, internal consistency).

## Inputs

- Notion property database (lat/long for each ORA property)
- Census ACS data (demographics, employment) — `api.census.gov` ACS 5-year (estimates + margins of error) when `CENSUS_API_KEY` is present in the shell environment; keyless Esri Living Atlas layers otherwise (see Ring Demographics). The key is read from the environment only — never stored in skill text, memos, Notion or logs; check presence by length only (`${#CENSUS_API_KEY}` in bash, `$env:CENSUS_API_KEY.Length` in PowerShell).
- BTS NTAD (highway, rail, intermodal) — public data
- Web search / Firecrawl for nearby anchor tenants and points of interest (no dedicated places/POI API is connected — this is a manual lookup, not a live query)
- Web search for submarket reports (CBRE, Cushman, JLL)
- **Drive-time routing** (see Drive-Time Method below): OpenRouteService (ORS) public API — `[GG: ORS API key needed — free signup at openrouteservice.org; set ORS_API_KEY in the environment]` — with a keyless OpenStreetMap-based OSRM public server (`router.project-osrm.org`) as fallback.
- **CoStar Underwriting/Market report PDF for the subject** (when supplied) — see CoStar Report Ingest below.
- **`ora_ring_demographics.py`** (deal folder `Business/Investment Candidates -- 2026`; run on the linked computer): `python ora_ring_demographics.py "<address>" [--radius 25] [--out ring.md] [--vintage YYYY] [--compare-vintage YYYY] [--source auto|esri|api]` or `--lat/--lon`. Implements the Ring Demographics recipe end to end, including the working-age proxy; with `CENSUS_API_KEY` set it takes attributes from `api.census.gov` (with MOE and the attainment delta), else the Esri layer. `--vintage` defaults to the latest ACS 5-year, `--compare-vintage` to vintage − 5.

## Standard Workflows

### Drive-Time Method (resolution ladder — try in order, label the result honestly)

Any step that needs a drive-time (isochrone population, labor pool, distance-to-anchor by road) resolves the travel time through this ladder and **states which tier produced the number** in the output:

1. **OpenRouteService (ORS) — preferred, needs a free key.** If `ORS_API_KEY` is present, call the ORS public API:
   - Matrix (many origins→destinations, durations): `POST https://api.openrouteservice.org/v2/matrix/driving-car` with header `Authorization: {ORS_API_KEY}`, body `{"locations": [[lon,lat],...], "metrics": ["duration"]}`.
   - Isochrones (true drive-time polygon for ring population): `POST https://api.openrouteservice.org/v2/isochrones/driving-car`, body `{"locations": [[lon,lat]], "range": [1800], "range_type": "time"}` (1800 s = 30 min). Intersect the polygon with Census block-group centroids for the 30-min population/labor pool.
   - Free tier ≈ 2,000 matrix calls/day, 500 isochrone calls/day — ample for ORA volume. Label: **"drive-time: ORS road network"**.
   - `[GG: ORS API key needed — free signup at openrouteservice.org]`
2. **OSRM public server — keyless fallback (verified live 2026-07-18, independently re-confirmed 2026-07-19 via a real `route` + `table` request between Columbus OH and Rickenbacker Inland Port — both returned valid duration/distance; re-confirmed 2026-09-28 with a 417-tract `table` pull for 4100 Perimeter Dr, batches of 90 destinations, 1 s pause).** If no ORS key, use the public OSM demo server (no key, best-effort, rate-limited — never for bulk production):
   - Route (point-to-point duration/distance): `GET https://router.project-osrm.org/route/v1/driving/{lon1},{lat1};{lon2},{lat2}?overview=false` → `routes[0].duration` (seconds), `.distance` (m).
   - Table (durations matrix): `GET https://router.project-osrm.org/table/v1/driving/{lon1,lat1;lon2,lat2;...}?annotations=duration` → `durations` matrix (seconds).
   - OSRM has **no isochrone endpoint** — for ring population, sample candidate block-group centroids within a straight-line radius and keep those whose table-driving-time ≤ threshold. Label: **"drive-time: OSRM public OSM server (best-effort)"**.
3. **Straight-line approximation — LAST resort, always labeled as such.** If both ORS and OSRM are unavailable/erroring, estimate: road distance ≈ great-circle × 1.3 detour factor; time ≈ distance ÷ assumed speed (55 mph highway / 30 mph arterial / 20 mph urban). Label: **"drive-time: straight-line estimate (no routing service) — REPLACE with ORS/OSRM before any IC-grade figure"**.

Never present a tier-3 estimate as a routed figure; the tier label is mandatory in every memo/scorecard cell that carries a drive-time.

**Road-vs-straight-line gap flag (v1.8).** For any distance that feeds a Location Score band (interstate, intermodal, rail), compute both the great-circle distance and the OSRM road distance. If road distance exceeds 2x straight-line, flag it in the memo and score on the road distance; state the straight-line figure beside it. A third-party claim (CoStar, OM) that sits outside both figures is reported as a conflict, not adopted.

### Ring Demographics (keyless recipe added v1.7, script v1.8, `api.census.gov` key path v1.9)

Use when a memo needs 3/5/10/15/25-mile and 15/20/30-minute population, households, median household income and median age around the subject. The recipe is implemented in `ora_ring_demographics.py`; the steps below document what it does.

1. **Geocode** the address with the Census geocoder (`geocoding.geo.census.gov/geocoder/geographies/onelineaddress`, benchmark `Public_AR_Current`, vintage `Current_Current`) → lat/lon plus the subject's tract GEOID.
2. **Pull tract centroids** from the keyless Esri Living Atlas layer `.../P3ePLMYs2RVChkJx/arcgis/rest/services/ACS_Highlights_Population_Housing_Basics_Centroids/FeatureServer/2/query` (layer 2 = Tract; points in Web Mercator). Use `geometry={lon},{lat}`, `inSR=4326`, `distance` in meters (25 mi = 40,234 m), `outFields=GEOID,NAME,County,B01001_001E,B01002_001E,B19049_001E,B25003_calc_pctOwnE,B25002_002E,B01001_calc_pctLT18E,B01001_calc_pctGE65E`, `returnGeometry=true`, page with `resultOffset`/`resultRecordCount=50`. Convert x/y from EPSG:3857 to lat/lon; compute haversine miles. **On the API path (step 7) this layer supplies geometry and GEOID only** (`outFields=GEOID,NAME,County`); tract attributes come from `api.census.gov`, joined on GEOID (state + county + tract).
3. **Aggregate by centroid-in-ring** (no areal apportionment): sum population and occupied units; population-weight median household income and age. Drive-time rings: route the same centroids through the OSRM `table` endpoint (Drive-Time Method tier 2) and filter by minutes. Only tracts within the pulled radius are routed, so a drive-time figure whose true reach extends past the radius is a **floor** — say so.
4. **Working-age population proxy (v1.8; Location Score component 4).** Per tract: population × (100 − %under-18 − %65+) ÷ 100, summed over the ring. It is a proxy for ages 18–64, not an occupation-specific labor pool; label it "working-age population (18–64 proxy)" and never call it a labor pool of relevant occupations without an occupation cut. On the API path the same figure is computed from exact B01001 cells (total less the male/female under-18 and 65+ cells) rather than rounded percentages, so it can differ slightly from the Esri path (4100 Perimeter Dr, 30-min ring, ACS 2023: +24 on 782,831, 0.003%).
5. **Execution surface.** The cloud session's WebFetch tool rejects these query URLs as too long (proxy 403, confirmed 2026-09-28) and must not be bypassed with curl. Run the pull as a short Python script on the user's linked computer (`device_bash`, urllib, network per the account's egress setting) and paste results back; if no linked computer is available, state the gap rather than estimating. `CENSUS_API_KEY` must be visible to the shell that runs the script (a Windows user environment variable; check length only). Cowork VM and cloud sandboxes do not inherit it, so the API path runs on the linked computer only.
6. **Label** every figure. No key: "Esri ArcGIS Living Atlas ACS tract layer (keyless), centroid-in-ring; drive-time: OSRM public OSM server (best-effort)"; that path carries no MOE, so note that tract MOEs are wide (a single tract's median income can carry ±13%). Key present: "api.census.gov ACS 5-year <vintage>, centroid-in-ring" plus the same drive-time label. No tract centroids may fall within 1 mile of an infill site — report no 1-mile ring rather than 0.
7. **Census API path (v1.9) — use it whenever `CENSUS_API_KEY` is present in the environment; the Esri path above is the no-key fallback, unchanged.** Pull, per county in the pull, `api.census.gov/data/<vintage>/acs/acs5?...&for=tract:*&in=state:SS county:CCC`: B01001 (total + age cells), B19013 median HHI, B01002 median age, B25002 occupied units, B15003 attainment, each with its `…M` margin of error, joined to the centroids on GEOID (≤45 variables per request; treat Census sentinels ≤ −100,000,000 as unavailable). Ring MOE: sums by the Census root-sum-of-squares method; population-weighted medians are approximate, so report the tract-MOE range and flag it approximate. `--vintage` defaults to the latest ACS 5-year, `--compare-vintage` to vintage − 5. **Attainment delta:** bachelor's+ share of population 25+ (B15003 022–025 ÷ 001), current vs. vintage − 5 (non-overlapping windows), compared at **county/CBSA level, never tract level**, because tract boundaries change between vintages — state that in the output. County set: the counties holding at least one centroid inside the 30-min drive ring (for Location Score step 4, the subject's metro CBSA counties); state which set was used. Label the delta "CONFIRMED (api.census.gov ACS 5-year B15003)" with MOE (Census proportion formula, root-sum-of-squares across the two vintages). Never print, log or write the key: URLs in logs use `key=***`; an HTML "Missing Key"/"Invalid Key" page means stop and report, with one retry at most. No key: report the current Esri attainment level only and flag the delta as an explicit UNVERIFIED gap (Living Atlas layers overwrite in place; no historical vintage).

### CoStar Report Ingest (added v1.7, extended v1.8)

Runs whenever a CoStar Underwriting/Market report for the subject is in hand (extract with `pdftotext -layout`; charts have no text layer, tables do). Feeds Location Score component 5 and IC Memo §4.

1. **Submarket vs. peer-set divergence test.** Record submarket vacancy/availability (Submarket Summary), the peer-set vacancy/availability (Peer Properties Summary) and the peer-submarkets figure. **Trigger: submarket vacancy above 15%, OR submarket vacancy more than 2x the peer-set vacancy.** On trigger: (a) read the submarket vacancy history table for a step change (a jump of 10+ points in one year points to a few large blocks, not broad weakness — state as an inference until building-level data is seen); (b) compute the product mix (logistics vs. flex share of inventory) and say which product the headline describes; (c) **request the submarket vacancy by size band (and the largest vacant blocks) from CoStar or the broker before any IC or lender use**; (d) flag the lender/appraiser narrative risk — the headline is what an appraisal will quote. Never let the submarket headline alone switch Bear-mode on or off; state both figures.
2. **Rent basis tagging — asks AND executed leases (v1.8).** Every rent taken from CoStar or a listing carries a basis tag: NNN / modified gross / full-service (FS) / gross / +UTIL / unstated. Do not average rents across bases; do not compare an unstated-basis rent to an NNN model input without saying so. Report the size of the suite each ask sits on (asks on 4,000–6,000 SF suites do not price a 30,000+ SF block). **Executed lease rents get the same tagging before they enter any comp grid.** An FS or gross executed rent is never entered into an NNN comp grid unconverted: show the NNN-equivalent beside it with the OpEx proxy used, tagged [est] and stating the source of the proxy; keep asking rents and executed rents in separate columns. Origin: the 4100 Perimeter Dr location analysis compared NNN asks with executed starting rents that were full-service ($8.95 and $9.00 "/fs") and overstated the rent gap until corrected in v03.
3. **Size-fit check.** Compare the subject's block size to (i) the largest peer availability, (ii) the lease-comp deal-size distribution (low/median/high), and (iii) 12-month peer leasing volume and average deal size. If the subject exceeds the largest peer availability or the lease-comp median by 3x or more, state "no direct leasing evidence at this block size" and route the demising question (sprinkler / fire-area / parking ratio per 1,000 SF vs. available peers) to the DD-critical list. Geocode block-size comps so the distance to the subject is computed, not asserted.
4. **Nearby pipeline.** From the Under Construction and Deliveries pages list every project within 1.5 miles (and total SF within 5 miles): SF, clear height, start/delivery, % leased, distance. Cross-check CoStar's own submarket summary against its construction pages (the summary can say "nothing under construction" while the pages list starts) and flag the inconsistency. Illustrate the vacancy effect only as arithmetic, tagged [SPECULATIVE] where inventory-base inclusion is unconfirmed.
5. **Internal-consistency checks (v1.8).** Before any CoStar figure enters a memo, test the report against itself and against geocodes, and report each disagreement rather than resolving it silently: (a) Submarket Summary vs. Under Construction / Deliveries pages (pipeline stated vs. listed); (b) every distance claim (rail, highway, intermodal, anchor) vs. a geocoded great-circle and OSRM road distance — apply the road-vs-straight-line gap flag; (c) entity and ownership names that conflict across pages (owner, tenant, developer, landlord); (d) submarket forecast (absorption, vacancy, rent) vs. the pipeline and deliveries the same report lists; (e) rent-basis or unit conflicts between summary tables and lease-comp tables. Output a short consistency table (check / result / evidence / action) in the data-gaps table.
6. **Source-conflict exhibit.** Where two or more of CoStar, CBRE, Colliers, Cushman & Wakefield, Matthews, JLL, Newmark publish the same metric (vacancy, availability, asking rent, absorption, under construction, cap rate, $/SF), tabulate them side by side with the period and stated definition; do not average and do not silently pick one. Note the spread; for sub-50,000 SF Class B/C assets treat the CoStar peer set as the closest evidence and say why.
7. **Exit-cap evidence count.** Report the number of cap-rate observations behind any exit cap (selected comps, submarket, metro). Fewer than 5 observations → label the exit cap "thin support" in the memo.
8. **Output.** A one-page "Submarket vs. Peer Set" exhibit for IC Memo §4 (table + three-line reading + data requests) and a data-gaps table including the consistency table. Mark [gap], [est], [SPECULATIVE] on anything not verified.

### Acquisition Location Score (1–100)

The score is a DD/context input for IC Memo §4, not a Stage 2 scorecard input. Composite = Σ (component score 0–100 × weight). Score each component from the band table below; state the raw measurement, the band and the score for every component.

1. Distance to nearest interstate (weight 25%).
2. Distance to nearest intermodal (BNSF, NS, CSX) — for industrial (weight 20%).
3. 30-min drive-time population (weight 15%) — resolve travel time via the Drive-Time Method ladder above (ORS → OSRM → straight-line), labeling the tier; use the Ring Demographics recipe for the population sum.
4. 30-min drive-time labor pool of relevant occupations (weight 15%) — same Drive-Time Method ladder for the ring (working-age proxy from the Ring Demographics recipe), PLUS a mandatory sub-step: metro-level bachelor's+ educational attainment, confirming labor QUALITY (not the ring itself — see Boundaries). **If `CENSUS_API_KEY` is present (check length only), this is the primary method: `api.census.gov` ACS 5-year table B15003, current vintage and vintage − 5, compared at county/CBSA level (Ring Demographics step 7) — cite as "CONFIRMED (api.census.gov ACS 5-year B15003)" with the MOE; the 5-year delta is then CONFIRMED, not a gap.** **No-key fallback (2026-08-24 method, unchanged): Esri ArcGIS Living Atlas hosted keyless FeatureServices** — `ACS_Highlights_Population_Housing_Basics_Centroids` (org `P3ePLMYs2RVChkJx`, county/tract layers, population/age bands, ACS 5yr current vintage) for the population/age cut, and `ACS_Educational_Attainment_Boundaries` (same org, same vintage, table B15002) for attainment — both keyless, paginated via `resultOffset` (maxRecordCount=50/request). Query every county in the subject property's metro CBSA and sum; cite as "CONFIRMED (Esri ArcGIS Living Atlas, ACS 5yr B15002/B01001, keyless FeatureService)". **Known gap (no-key path only):** Living Atlas layers auto-update in place annually and do NOT preserve versioned historical snapshots (confirmed 2026-08-24 — two candidate historical `arcgis.com/sharing/rest/content/items/{id}` lookups either 404'd or resolved back to the current live service), so the 5-year-prior anchor (e.g. 2019 vs. current) this step used to pull from `census-acs-extract` is NOT obtainable this way — report the current-year attainment level/share only and flag the 5-year delta as an explicit UNVERIFIED gap rather than fabricating or omitting it silently. When `CENSUS_API_KEY` is present, the API path above applies instead and this Esri path is not used for the attainment figure.
5. Submarket vacancy and rent growth trend (weight 15%) — run the CoStar Report Ingest divergence test first; score on the peer-set figure where the submarket headline is flagged as distorted, and state both.
6. Major employer / anchor tenant proximity (weight 10%).
7. Output: location score memo (DOCX) with composite score and component breakdown.

#### Score bands (PILOT — added v1.8; not yet ratified by Gabriel)

Every composite produced from this table is labeled **PILOT**, and any component measured on an estimated input is tagged [est]. Until Gabriel ratifies the bands, a memo may quote the pilot composite only beside the score it previously carried, with the difference explained. Distances are routed road miles where the road-vs-straight-line gap flag applies.

| Component | 100 | 90 | 80 | 65–75 | 45–55 | 25–35 | 10–15 |
|---|---|---|---|---|---|---|---|
| 1 Interstate access (road mi to a full interchange) | ≤1.0 | ≤2.0 | ≤3.0 | 3–5 → 65 | 5–8 → 45 | >8 → 25 | — |
| 2 Intermodal (road mi) | ≤5 | 5–10 → 85 | 10–20 → 70 | 20–35 → 50 | 35–60 → 30 | >60 → 15 | — |
| 3 30-min population | ≥1.5M | 1.0–1.5M → 90 | 0.5–1.0M → 75 | 0.25–0.5M → 55 | 0.1–0.25M → 35 | <0.1M → 15 | — |
| 4 30-min working-age population (18–64 proxy) | ≥1.0M | 0.6–1.0M → 85 | 0.3–0.6M → 65 | 0.15–0.3M → 45 | 0.05–0.15M → 25 | <0.05M → 10 | — |
| 6 Anchors / major employers | ≥3 within 3 mi | 2 within 3 mi → 80 | 1 within 3 mi → 60 | anchors only 3–10 mi → 40 | none within 10 mi → 15 | — | — |

Read each row as: the measurement on the left of an arrow maps to the score after it; a bare threshold in a column scores that column's header value. Component 5 (submarket trend) is scored separately:

- Base score from the vacancy used for scoring (peer-set figure where the divergence test flags the headline; otherwise submarket): ≤5% → 90; 5–8% → 75; 8–12% → 55; 12–18% → 35; >18% → 15.
- Rent-growth adjustment, 12-month asking or executed growth on a stated basis: above +4% → +10; 0% to +4% → 0; below 0% → −10. Clamp at 0–100.
- Report both vacancy figures whenever the divergence test triggers, and state which one scored.

**Missing inputs.** If a component cannot be measured, mark it [gap], mark the composite PARTIAL, and renormalize the remaining weights to 100%; state the weights used. Never score a missing component at a neutral value.

**Estimated inputs.** A component scored from an unrouted or unverified measurement (straight-line highway distance, unconfirmed rail distance, a CoStar distance claim not reproduced by geocode) carries [est] on the component and on the composite.

### Submarket Comparison

2. Normalize scores; produce ranking.

### Last-Mile Suitability
1. Distance to population centers (5/10/15 mile rings).
2. Truck-court and dock-door inventory.
3. Highway access / signal density.
4. Output: last-mile scorecard (xlsx).

### Tenant Mix Optimization
1. For an existing property, plot current tenants by industry.
2. Identify gaps relative to submarket employment composition.
3. Output: tenant mix recommendation memo (DOCX).

## Boundaries

- Forecasts of demographic change marked [FORECAST].
- Census data lag is acknowledged (typically 12–24 months).
- Drive-time figures follow the Drive-Time Method ladder (ORS road network → keyless OSRM public server → straight-line estimate) and **must state which tier produced them**. ORS needs a free API key (`ORS_API_KEY`; see the placeholder in Inputs) — until it is set, live routing runs on the keyless OSRM public server (best-effort, not for bulk production), and only falls to a straight-line estimate if both are unavailable. If a dedicated routing MCP connector is ever added, prefer it and update this line and tech.md together.
- **`CENSUS_API_KEY` present → `api.census.gov` path (v1.9).** With the key in the shell environment, Ring Demographics attributes and Location Score step 4 attainment come from `api.census.gov` ACS 5-year (estimates + MOE, current AND vintage − 5), and the attainment delta is CONFIRMED. The key is never stored in skill text, memos, Notion pages, logs or git; presence is checked by length only, and request URLs are masked (`key=***`). The key is a Windows user environment variable: shells launched by the Claude desktop app inherit it after an app restart, but Cowork VM / cloud sandboxes do not — there, or with no key, use the no-key path below and label it. `api.census.gov` returns an HTML "Missing Key"/"Invalid Key" page without a valid, activated key: stop and report, one retry at most.
- **No-key path — metro attainment (step 4) permanently repointed 2026-08-24** to the keyless Esri ArcGIS Living Atlas FeatureServices (`ACS_Highlights_Population_Housing_Basics_Centroids` + `ACS_Educational_Attainment_Boundaries`, org `P3ePLMYs2RVChkJx`) — `census-acs-extract` retired 2026-08-05 with no successor, and its archived script (`_archive/census-acs-extract_retired-2026-08-05/census_acs_extract.py`) is not present in every session's synced-skills cache (confirmed absent 2026-08-24; only lives in the full `ora-skills` repo checkout), so it is no longer a dependable manual fallback either. Living Atlas closes the CURRENT-year attainment confirmation but not the 5-year-anchor delta (layers overwrite in place, no versioned history — see step 4). On this no-key path, report the 5-year delta as UNVERIFIED. Don't conflate attainment with the drive-time ring: a CONFIRMED attainment figure does not mean the drive-time ring is routed at ORS/OSRM quality — check the tier label on that figure separately.
- **CoStar Report Ingest limits (v1.7):** CoStar forecasts, submarket summaries and construction pages can disagree with one another within the same report; report the disagreement, do not resolve it silently. Peer-set and lease-comp statistics rest on small samples (often 2–20 observations) — carry the count. A CoStar submarket boundary is CoStar's, not a neighborhood's (4100 Perimeter Dr sits in "Downtown West"); name the submarket as CoStar defines it.
- **Ring Demographics limits (v1.7, amended v1.9):** centroid-in-ring counting, no MOE on the Esri path (the API path carries MOE; population-weighted medians stay approximate), OSRM best-effort routing, and radius-truncated drive-time figures are floors; state them with the numbers. The working-age figure is an age-band proxy, not an occupation-specific labor pool.
- **Score bands (v1.8):** the band table is a pilot rubric pending Gabriel's ratification; every composite from it is labeled PILOT. Do not change component weights without Gabriel's instruction.
