# daily-brief — Changelog (v2.0–v2.9)

Archived from `SKILL.md` 2026-08-14 (ORA Automation Audit Revision 9 remediation — repo-only, excluded from packaging). Current version's changelog entry lives in `SKILL.md` itself; only superseded entries move here going forward.

- **v2.9 (2026-08-11):** Corrected the **Patch 3 pre-create dedup guard's 1-match branch**, which overwrote unconditionally. It assumed any same-day `Daily Brief — [DATE]` page is this run's own retry artifact; during a catch-up burst it is a *completed prior fire's published brief*, so `replace_content` destroyed a brief Gabriel may already have read. Overwrite is now permitted only for a page **this session created**; any other match is treated as a completed prior run — skip publication AND the Outlook send, report a NORMAL skip. Also documented that the guard never covered the send leg at all (it dedup'd the Notion page only, while the COM send below was unconditional), so an unattended caller needs a real entry guard plus a Sent-Items probe on top. Found via the 2026-08-09 `ora-am-brief` double-fire (09:06 + 09:11 ET), where the second fire avoided clobbering page `3b76ecd8-…` only because a human-directed stand-down happened to intervene. `ora-am-brief` has carried a task-local override (B.0.1) since 08-09; this fixes the shared skill for every other consumer.

Found: the 2026-07-16 fix corrected Notion/workbook for two tenants but never touched the matching HubSpot Lease Renewal deals, which still carried the disproven `2026-07-31` date nine days later; a third tenant (J&R Enterprises) had its HubSpot deal actively edited *toward* that same wrong date on 2026-07-21. Section 4b's DISCREPANCY check now also pulls the tenant's HubSpot deal and compares its closedate against the workbook when a two-way mismatch already fired.
