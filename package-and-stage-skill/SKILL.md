# package-and-stage-skill (v1.32)

Companion to `ora-skill-store-drift-check`. Turns a "repo newer → re-upload to Cowork/claude.ai needed" finding (or any repo skill edit that must reach the platform) into one staged, one-click installer.

**Source of truth = the git repo** `C:\Users\Owner\ora-skills\<skill>\SKILL.md`. The AppData runtime cache is a read-only mirror that rebuilds from the platform after import — never write it directly (2026-06-11 Roaming-alias clobber incident).

**Registration is human-gated.** This skill packages and stages; it does NOT install. A session cannot write the skill registry — Gabriel clicks **Save skill** (or Settings → Capabilities) on the staged `.skill`.

**A publish/unpublished claim in a Rev-log or advisory must be freshly sourced, never carried forward.** Before ANY session writes a sentence asserting a skill IS or IS NOT currently published/enabled, run `python tools\skill_drift_report.py --publish-status <skill ...>` and cite its verdict + `checked_at` timestamp inline. A prior Rev-log's claim, memory, or the body H1 version marker alone is not evidence of current publish state — only a fresh run of this flag (or, from Cowork, a live `ListSkills` account call) counts. **Read references/incident-history.md § Publish-status claims before writing any such sentence.**

## Input

- **Entry point A (package + stage, default):** one or more skill names. Default: the skill(s) the latest drift-check comment flagged **repo-newer**, or the skill(s) returned by `python tools/pending_reimport.py candidates` — the UNION of the post-commit PENDING-REIMPORT ledger and a fresh full repo-vs-cache SHA256 sweep. **Never use `pending_reimport.py list` alone as the candidate source** — the ledger only records commits made after the hook existed (2026-07-16), so trusting `list` silently skips pre-hook drift. `candidates` is read-only; `backfill` persists sweep-only findings into the ledger. Full note: `references/incident-history.md` § Entry point A candidate source.

  **Surface boundary — a Cowork-bash `candidates`/`sweep_drift` run cannot see the runtime cache** (`CACHE_ROOT` has no mount in the sandbox, so `skill_drifted()` reports zero cache-side drift regardless of ground truth). Treat such a result as **repo-side-only**: ledger union and shared-dep direction checks stay valid; "no candidates" is NOT verified absence of cache drift. Re-run from a Code-surface Windows shell, or verify the cache independently (the Read tool reaches it), before proceeding. Full note: `references/incident-history.md` § Cowork-bash cache blindness.
- **Entry point B (pre-packaged install):** explicit path(s) to already-built `.skill` file(s) handed off by an earlier session or another surface, with instruction NOT to repackage. Runs the integrity pre-check below, then steps 5–8 only.

## Entry point B — pre-packaged install (steps 5–8 only)

When handed pre-built `.skill` files, do NOT re-run steps 1–4 and do NOT repackage — but never install on trust alone (packages go stale, or were never built). **The handoff's premise is a claim, not a fact — item 1 tests it, and runs before anything else.**

**Bridge-first freshness screen — ONE cheap check before the per-package pre-check, whenever the Desktop Commander bridge is live.** Cross-check (a) a live `ListSkills` call — does the target skill's description already show the cited version, enabled; and (b) a Desktop-Commander SHA256 compare between the skill's AppData `skills-plugin` cache copy and its current repo copy. Both matching = the click already happened: skip the per-package pre-check, `present_files` and the Save-skill ask for that package; go straight to Step 7's "already in sync" logging. Anything that doesn't clear the screen runs the full pre-check below. Incident: `references/incident-history.md` § Bridge-first freshness screen.

Replace steps 1–4 with this integrity pre-check, per package (for whichever packages the bridge-first screen above didn't already resolve):

1. **Exists — assert it, never assume it.** The `.skill` file is at the stated path. A hard assertion on every named path, run FIRST, never waived on a circumstantial-sounding handoff (real commit SHA, named packaging tool, plausible `_staging` path). If absent, sweep before concluding: the session's uploads dir, `ora-skills\_staging\` (incl. dated subdirs), `Downloads`, `Desktop`, and a filename search across `C:\Users\Owner`.

   **If no package is found anywhere → MISSING, not stale. Different finding, different remedy.**
   - **Stale** = a package exists but no longer matches the repo → REJECT and route back to Entry point A to *re*build.
   - **Missing** = no package was ever built → the handoff premise is false, and a "do NOT repackage" instruction does **not** bind. Proceed to Entry point A and build the FIRST package, stating plainly that the premise failed and why; do not stop and ask. Then run steps 0–8 in full — in particular step 0 (`plugin_of`) and step 1 (git-clean + `git log -1`), which Entry point B would otherwise skip.
   - Either way, **surface the discrepancy explicitly** rather than quietly repairing it. A claimed packaging run that never happened is a write-side reporting failure; an existence check that silently self-heals destroys the only evidence of it.

   Why asserted rather than assumed (the write-side counterpart of step 2's read-side hash rule): `references/incident-history.md` § Existence is asserted.
2. **Entries.** List zip entries: forward-slash paths, expected file set (`SKILL.md` plus any `references/`/`templates/`/`scripts/` files and, for `SHARED_ROOT_DEPS` consumers, the injected shared dep).
3. **Freshness.** SHA256 the packaged copy of each shared root dep against the CURRENT repo-root copy (and, where the handoff claims SKILL.md currency, spot-check it against the repo skill dir). EOL rule applies: raw mismatch → CRLF→LF-normalized re-compare → only a normalized mismatch is real. A stale package is REJECTED — route back through Entry point A to rebuild; never install a package that no longer matches the repo (stale ≠ missing — item 1).
4. **Stage.** Copy the verified `.skill` into the current session's outputs directory (`present_files` needs it there). **Also baseline the target cache directory's CreationTime here, unconditionally** — Entry point B skips step 2, so this is the only place the pre-click baseline step 7's fallback needs gets captured: `python tools/reimport_correlate.py baseline <skill>`.

**One-command pre-check (v1.33).** `python tools/reimport_correlate.py precheck <pkg.skill> [<pkg.skill> ...]` runs items 1–3 plus item 4's baseline in one call: existence (a MISSING package is reported as such, not as stale), forward-slash entries, no directory records, one top-level dir, `name`==dir, `description` ≤1024, `plugin_of` None, and every entry byte-identical to the repo copy (raw, then EOL-normalized; `SHARED_ROOT_DEPS` compared against the repo root). Repo files absent from the package are WARNed, not failed. The CreationTime baseline is captured only if none exists — never overwritten. Exit 1 on any FAIL; a FAIL means reject and route to Entry point A. It does not stage. **Connect `C:\Users\Owner\ora-skills\_staging` as a session folder at session start** — `device_stage_files` needs the grant and grants are per-session, so asking mid-run costs a round trip (2026-09-23).

Then steps 5–8 unchanged: `present_files`, Cowork Save-skill routing for multi-file skills, post-install cache verify, and the `event_log.md` log of the confirmed click.

## Procedure

0. **Plugin-membership routing — the WRONG-target gate (both entry points, run FIRST).** Check `python -c "import sys;sys.path.insert(0,'tools');from package_skills import plugin_of;print(plugin_of('<skill>'))"` (or `plugins/*/plugin-build.json`). A plugin name means the skill does NOT install via a standalone Save-skill click (a shadow copy lands; the plugin's loaded copy stays stale): **STOP the standalone path** and rebuild the plugin — `python tools/build_plugin.py <plugin> "<session outputs dir>" [--bump patch]`, `present_files` the `.plugin`, and on confirmed install verify the plugin cache mirror (`…\rpm\plugin_<id>\skills\<skill>\`, not the standalone skills-plugin cache) before clearing the ledger. **The repo side of that byte-comparison is the skill's canonical top-level dir** (`ora-skills\<skill>\SKILL.md`), NOT `plugins\<plugin>\skills\<skill>\` (resolves to a non-existent file → FALSE mismatch). Only if `plugin_of` returns `None` do steps 1–8 (standalone) apply. Incidents: `references/incident-history.md` § Plugin-membership routing.
1. **Confirm source.** `C:\Users\Owner\ora-skills\<skill>\SKILL.md` exists. Run `git status --short -- <skill>/`; if dirty, STOP and commit first — repo-first rule: the repo leads the platform, never the reverse. Record the last commit (`git log -1`).

   **Commit by pathspec, never bare — the shared-index race (v1.25).** `ora-skills` is a shared checkout and **the git index is shared state between every concurrent session.** A bare `git commit -m "…"` commits whatever is in the index at that instant, so another session's `git add` landing between your `git status` and your `git commit` rides into your commit under your message. Always name the paths:

   ```
   git commit -m "<msg>" -- <skill>/SKILL.md <skill>/references/…
   ```

   A pathspec-limited commit ignores the rest of the index and is the only form safe in this repo. Corollaries: (a) `git status` is a **snapshot, not a lock** — re-check `git diff --cached --name-only` immediately before committing and confirm it contains only your paths; (b) if it does not, do NOT `git reset` the extra paths away — that is another session's live WIP; commit by pathspec and leave it untouched.

   **Verify after committing, always:** `git show --stat --oneline HEAD` must list only your files. If it lists more, the sweep already happened — `git reset --soft HEAD~1`, `git restore --staged` the foreign paths, and recommit by pathspec. **Concurrency is the mechanism, not the pre-commit hook** (`tools/hooks/pre-commit` contains no `git add`; do not "fix" it). Incident and the wrong-fix near-miss: `references/incident-history.md` § Shared-index race.

   **Claim before you edit, when the session will make more than one commit (v1.26).** Pathspec makes each commit safe, not two sessions editing the same `SKILL.md` minutes apart. On the Code surface, claim each target skill dir via `~/.claude/hooks/lib/claim_work.py` before the first edit of a multi-commit session; release at hand-off. From Cowork with no bridge the claim is unreachable — say so in the hand-off rather than implying serialization. A claim is a visible declaration, not a lock. Why nothing routes there by default: `references/incident-history.md` § Claim before edit.

   **When the contested file is the one you are editing.** If `git status` shows the target skill's own `SKILL.md` staged or modified by another session, STOP and report rather than editing — that is an in-flight doctrine batch, and an edit now races a version bump you cannot see. Route to `dirty-tree-triage` (attribution + two-pass mtime settle) and `isolated-commit` (claim, stage, push). Contested WIP is reported, never force-resolved.
2. **Hash-compare the runtime cache for CONTENT, then gate the short-circuit on `main.log` — never on the hash alone.** Before packaging, hash-compare every file in the repo skill dir against `…\local-agent-mode-sessions\skills-plugin\<outer-UUID>\<inner-UUID>\skills\<skill>\` (SHA256 via `Get-FileHash`; same file count, names, hashes). **Normalize line endings before declaring drift:** the platform stores LF, git autocrlf gives CRLF — on any raw mismatch re-compare CRLF→LF-normalized, trailing-whitespace-trimmed; only a normalized mismatch is real drift, a raw-only mismatch is content-IN-SYNC. **A content match is not sufficient to STOP.**

   **Why the hash alone is not proof:** `tools/sync_appdata_mirror.py` (pre-commit Check 4) copies every staged skill's files into every existing AppData mirror on every commit, so once a skill has been installed once the repo-vs-cache hash matches by construction. Evidence priority: (1) `main.log` non-zero `Delta: N to download` → `Sync complete: N downloaded, 0 failed` for this skill at/after the current repo commit; (2) cache mtime vs a pre-click baseline; (3) hash-vs-repo, content-only. Incident (d03fe62): `references/incident-history.md` § Hash-match-by-construction.

   **Revised gate:** STOP (skip packaging) only when BOTH hold: (i) `main.log` shows a non-zero `Delta:` → `Sync complete: N downloaded, 0 failed` cycle for this skill at or after its current repo commit's timestamp, AND (ii) no pending line in `_staging/PENDING_REIMPORT.md` (`pending_reimport.py list`/`candidates`). Only then log the one-line `event_log.md` “already in sync” note (“`<skill>` already in sync at v`<X.Y>`, no reimport needed”) and stop. Otherwise — including a hash MATCH with no corroborating `main.log` cycle — proceed to step 3. **Shared root deps are part of the content comparison.** For `SHARED_ROOT_DEPS` skills in `tools/package_skills.py` (consumers of repo-root `target-markets.json`), the skill dir deliberately lacks the dep; the packager injects it at package time (see the skill dir's `PACKAGING-NOTE.md`). Hash-compare the REPO-ROOT copy against the cache's copy — a skill-dir-only comparison silently skips it; never copy the dep into the skill dir (duplicate zip entry). Incidents + the current consumer list: `references/incident-history.md` § Revised gate and shared root deps.

**`main.log` liveness — check it before trusting either side of the gate.** The desktop build can go quiet for a day or more between restarts; when `main.log`'s own mtime is stale relative to now, condition (i) can never be satisfied for ANY skill — treat that as "main.log unavailable," not "no install occurred," and fall back to the cache-directory CreationTime discriminator (step 7). **Baseline the cache directory's CreationTime during this pre-check UNCONDITIONALLY, every run** — without it, step 7's fallback is unusable exactly when it is needed. Observed case: `references/incident-history.md` § main.log liveness.

**There are TWO `main.log` files — check the Local one first.** `%LOCALAPPDATA%\Claude\Logs\main.log` (`Logs`, not `logs`) carries `[SkillsPlugin]` sync activity continuously; `%APPDATA%\Claude\logs\main.log` (Roaming) can be dark for a day. Fall back to CreationTime-only when BOTH are stale. **The Local log is skill-blind** — its `Delta: N` / `Sync complete: N` lines carry only a count — so a bare "a sync happened around then" is circumstantial. What works: **match the log timestamp against that skill's own cache-directory CreationTime move to the second** — skill-specific, first-hand, and it rules out the mirror-sync hook (which never touches `main.log`). Either signal alone is meaningful but not "log-confirmed." Discovery: `references/incident-history.md` § Two main.log files.

**Run that correlation with `tools/reimport_correlate.py` — it is scripted, don't do it by eye (v1.31).** Two commands, at the two moments this skill already stops at:
   - `python tools/reimport_correlate.py baseline <skill> [<skill> ...]` — run at the **unconditional CreationTime baseline** (step 2, or Entry point B's integrity pre-check item 4). Writes `_staging/reimport-baselines/<skill>.json`.
   - `python tools/reimport_correlate.py verify <skill> [<skill> ...] [--baseline "YYYY-MM-DD HH:MM:SS"]` — run at **step 7**, after Gabriel confirms the click. `--baseline` covers an ad hoc check with no prior `baseline` call.
   - `python tools/reimport_correlate.py postclick <skill> [--version X.Y] [--no-append] [--clear-ledger]` — the whole after-"saved" sequence in one call (v1.33): both `main.log` liveness lines + last sync events, `verify`, and **only on CONFIRMED** the dated `event_log.md` append via `append-event-log.py --entry-file` (exit 0 required; `--version` defaults to a `version:` frontmatter token if the skill has one, else the entry omits it). `--clear-ledger` runs `pending_reimport.py clear` only after the append exited 0. Any other verdict STOPS: log tail printed, nothing appended, exit 1 — do not repackage, edit or commit. `--no-append` verifies only and is safe to re-run.

   It reuses `CACHE_ROOT` from `pending_reimport.py`, reads both `main.log` paths (Local first), and matches to the second (±1s). Verdicts: **CONFIRMED** (CreationTime moved AND an exact-second `Delta`/`Sync complete` pair — install proven) · **MOVED-ONLY** (moved, no correlating log line — first-hand but NOT proof) · **NO-CHANGE** (no reimport since baseline) · **NO-BASELINE** (the failure the unconditional baseline prevents). **Surface boundary:** Code-surface or DC-bridge only — from Cowork bash it inherits `pending_reimport.py`'s `CACHE_ROOT` blindness and its verdict is not trustworthy.

**Same-token content drift — the version token is not a content signal (v1.30).** A commit can change packaged bytes without moving the version marker, so the store serves stale bytes under a current-looking token. The token can only falsify (a store token BEHIND the repo proves drift), never confirm. The check that catches it: **cache-directory CreationTime vs the last commit touching the skill's packaged files** (`git log -1 --format=%ci -- <skill>/`) — CreationTime older than that commit = stale store. Run it whenever ledger and token disagree, and on any "refactor"/"extract"/"docs" commit. Incident (`577397f`): `references/incident-history.md` § Same-token content drift.

**A shared-dep hash mismatch is not automatically "reimport needed" — check direction first.** The cache may be a stale older version (fix = repackage + reimport) OR hold runtime-only content never committed to the repo (fix = commit the cache content back FIRST — reimporting would DOWNGRADE the runtime). Never assume direction by eye. Run `python tools/pending_reimport.py shared-deps` (or read the direction-aware advisory block `candidates` appends) and act on the label: `REPO-AHEAD`/`MISSING-IN-CACHE` → package + reimport as normal; `CACHE-AHEAD`/`DIVERGENT` → **STOP**, surface the runtime-only content to Gabriel to commit (CACHE-AHEAD) or reconcile by hand (DIVERGENT) before any reimport; `UNKNOWN` → git history unavailable, verify direction by hand.
2a. **Pre-flight frontmatter gate (v1.21).** A `description` over **1024 characters**, or a frontmatter `name` not byte-identical to its directory, makes the importer reject the `.skill` with **no error text anywhere** — the Save-skill click is a no-op. `tools/package_skills.py` catches both; on paths where it cannot run (cloud Cowork without the DC bridge, hand-built `_staging` packages, any `.skill` assembled without the repo) assert it yourself — **Read references/host-shell-snippets.md § Pre-flight frontmatter gate snippet before asserting by hand** (quoted `name:` scalars are legal; strip quotes before comparing, as the packager does).

    **Check the budget BEFORE editing a description, not after (v1.27).** `python tools/description_budget.py <skill>` reports `N/1024` and headroom; `--budget <chars>` exits non-zero unless the skill can absorb an edit of that size; no arguments ranks every skill tightest-first. Learning this at package time costs an edit-trim-recheck cycle every time.

    A hand-built archive also skips the packager's entry rules — assert those too: forward-slash entries only (backslash → importer rejects, APPNOTE 4.4.17.1), no directory records, `<skill>/SKILL.md` at the expected path. `zipfile.ZipInfo` with explicit arcnames satisfies all three; `shutil.make_archive` and `Compress-Archive` do not. **Report `description N/1024` and the `name`/dir pair rather than a verdict.**

    Authoring a skill cloud-side does not exempt step 1: read `C:\Users\Owner\ora-skills\<skill>\SKILL.md` over the bridge before editing — never the `~/.claude/skills/synced/` mirror, which serves the last *imported* version and silently lags any un-reimported commit.

3. **Package — sanctioned tool ONLY.** Via Desktop Commander on Windows: `python tools\package_skills.py "<session outputs dir>" <skill ...>`. NEVER PowerShell `Compress-Archive` (backslash zip entries → importer rejects). A non-zero exit is a real defect — surface it verbatim, never work around it. **Host-shell discipline — SKILL-WIDE.** Every Desktop Commander PowerShell invocation anywhere in this skill that uses `$` variables or spans multiple statements goes in a `.ps1` file run via `powershell -NoProfile -ExecutionPolicy Bypass -File <path>`, never an inline `powershell -Command` one-shot — `$` tokens are stripped in transit. Default to the `.ps1` pattern; do not try inline first. Incident (recurred 5×): Changelog v1.18(b).

   **Canonical invocation (copy, don't re-derive).** Write the script with Desktop Commander `write_file` to an absolute path under the repo or `_staging` (never a temp path the host can't resolve), then run it:
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "<absolute-path-to-script>.ps1"
   ```
   Inside the `.ps1`, use one `Set-Location` line (or fully-qualified paths) — Windows PowerShell 5.1 has no `&&` statement separator and throws `InvalidEndOfLine` on `cmd1 && cmd2`. `$` variables and multi-statement logic are unrestricted inside the file.

   **`Start-Process -ArgumentList` splits on spaces — and EVERY ORA root has spaces (v1.27).** Pass ONE pre-formatted string with every path quoted inside it, never the array form — the array form does not error, it runs against the wrong target (`C:\Users\Owner\OneDrive` instead of the Business tree) and prints a confident result. Sanity-check the item count any detached job reports before believing its verdict. **Read references/host-shell-snippets.md § Start-Process -ArgumentList before writing any detached PowerShell job.**

   **Resource-lint any skill that ships `scripts/`, before packaging (v1.27):** `python tools/script_resource_lint.py <skill>`. Flags `openpyxl.load_workbook()` without `read_only=True`, unbounded `pandas.read_*`, whole-file `.read()`, materialised recursive walks, and the `Start-Process -ArgumentList` array form. Advisory, not blocking; silence a deliberate hit with `# resource-ok: <reason>` on the flagged line. No other gate looks at resource behaviour — "it only reads files" is not a resource argument. Incident (9.1 GB, model-bulk-edit v1.0): `references/incident-history.md` § Resource lint.
4. **Stage.** Emit the `.skill` into the current Cowork session's outputs directory (maps to `/mnt/user-data/outputs`). **Cloud Cowork sessions:** the packager runs on the Windows host and cannot write a cloud session's outputs — emit to `ora-skills\_staging\<date>\`, connect `C:\Users\Owner\ora-skills` as a session folder and `device_stage_files` the artifact (folder grants are per-session — request once at session start); fall back to a base64 bridge with end-to-end SHA256 verification only when no folder can be connected. Byte-identity of the staged copy is asserted by hash, never assumed.
5. **Surface.** `present_files` the `.skill` → renders the **Save skill** install button.
6. **Route multi-file skills to Cowork, not desktop Settings.** If the skill has ANY file beyond `SKILL.md` (`references/`, `templates/`, `scripts/`), install via the Cowork **Save skill** button, not Settings → Capabilities → Skills: the desktop Settings single-`.skill` upload path silently drops subfolder files on import (reproduced twice, 2026-07-11). Single-file skills are unaffected by either path.
7. **Verify post-install, then log the click — not just the commit.** After Gabriel confirms installation, check the AppData runtime cache mirror contains every file the packaged `.skill` did — not just `SKILL.md`. Any missing file = the install silently failed (most likely the desktop-Settings bug above); tell Gabriel to re-install via Cowork. **Then run `python tools/reimport_correlate.py verify <skill>`** for the CreationTime/`main.log` correlation — verdicts and limits in the correlation-tool note above.

   **Cache-directory CreationTime is the discriminator between a real re-import and a mirror-sync overwrite (main.log-unavailable case).** `sync_appdata_mirror.py` rewrites bytes in place and leaves the skill directory's CreationTime untouched; a genuine Save-skill install tears down and recreates the directory, so CreationTime moves to the click time and every file inside shares it. When `main.log` is unavailable, compare CreationTime against the pre-click baseline — moved = first-hand evidence of a real re-import; unchanged with matching hashes = the hash-match-by-construction case. Live confirmation: `references/incident-history.md` § CreationTime discriminator.

   Once verified, log the confirmed install to `event_log.md` in the same pass: skill name(s), version, confirming timestamp, and that this was Gabriel's **Save-skill click**, not merely the repo commit — an unlogged click is the 2026-07-15 redundant-dispatch gap step 2 catches, and this entry is what lets a later pre-check trust "already installed". **Then clear the skill from the post-commit ledger:** `python tools/pending_reimport.py clear <skill>`. The verified cache re-sync is the ONLY thing that clears an entry — a commit sets it, a confirmed install clears it.

   **Surface boundary (Cowork sessions cannot write `event_log.md` directly).** `event_log.md` and `append-event-log.py` live under `C:\Users\Owner\.claude\...`, fail-closed to Cowork mounting with no partial carve-out. In a Cowork session, step 7 prepares the exact `event_log.md` entry line(s) and hands them to Gabriel to run through `append-event-log.py --entry-file <path>` (never stdin — cp1252/encoding gotcha) from a Code session. Step 7 is NOT complete, and the ledger is NOT cleared, until that Code-side write is confirmed. On the Code surface, step 7 runs in-session. Evidence: `references/incident-history.md` § Cowork cannot write event_log.md.

   **Bridge carve-out — the boundary binds only when the session has no path to the Windows host.** With the Desktop Commander bridge (`mcp__remote-devices__Desktop_Commander__*` tools live) step 7 runs IN-SESSION: `python C:\Users\Owner\.claude\maintenance\append-event-log.py --entry-file <path>` (never stdin). Two hard rules: (a) the entry file MUST start with a dated `## YYYY-MM-DD -- <title>` header or the appender exits 1; (b) confirm the append's exit 0 BEFORE `pending_reimport.py clear` — never batch the append and the clears into one script. The hand-to-Gabriel path is the fallback ONLY for bridge-less Cowork sessions. Incident: `references/incident-history.md` § Bridge carve-out.

   **Never trust a pre-staged `_staging` draft without a fresh verify — and archive it once its package is confirmed installed.** `_staging/<date>/` is shared scratch many concurrent sessions write into; pre-written log-entry drafts, hash claims, or verdicts found there are of unknown provenance. Re-derive `plugin_of`/git-log/hash/cache-state facts fresh every time. Once a package's install is confirmed, logged, and its `PENDING_REIMPORT` entry cleared, move its spent `_staging/<date>/` artifacts to `_archive/<date>_<context>/` — never delete (Hard Invariant 6). Incident: Changelog v1.19.
   **CLOSING SWEEP — run at the END of the session too, not only before packaging.** The pre-packaging run answers "is this skill safe to package"; cache-ahead content can appear at any point in a session (a concurrent session, or a Save-skill click on a skill built elsewhere). Before signing off, run **all three**:
   - `python tools/repo_first_check.py` — must end `no cache-ahead skills`. A **CACHE-AHEAD** result is urgent: pre-commit Check 4 (`sync_appdata_mirror.py`) will overwrite the newer cache copy on the next commit touching that skill. The tool auto-rescues to `_staging/repo-first-rescue/<skill>/` — reconcile it into the repo before anything else touches that skill.
   - `python tools/frontmatter_sweep.py` — must end `0 finding(s)`. The per-skill gates only see what you packaged or staged; this sees all of them.
   - `python tools/verify_installed_cache.py [<skill> …]` — reads what the PLATFORM holds, for anything installed this session.
