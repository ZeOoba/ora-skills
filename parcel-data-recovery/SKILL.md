# Parcel Data Recovery — ORA Off-Market Screens

Recovers the inputs that block P1 Buy Box economics (building SF, market value, year built, delinquency) from county GIS/CAMA sources, then recomputes P1 and rebuilds the off-market master workbook.

## Iron rules

1. **Never fabricate.** Unrecoverable parcels are omitted from recovery CSVs, never estimated.
2. **Never overwrite shipped data.** Recovered SF/values fill blanks only. QC asserts zero overwrites.
3. **Provenance per row.** Every filled cell carries a `SF Source`/`Value Source` tag with method + endpoint.
4. **Footprint SF is a floor.** Footprint-intersect methods give ground-floor area; multi-story GBA is understated. Tag `method=footprint_intersect`; keep stories where available.
5. **Stale values never rank.** Values older than the current assessment cycle (e.g., Wyandotte 2019) are tagged `[STALE est]`, verdicts carry the tag, and stale rows are excluded from cross-market Top-100 ranking.
6. **Versioning.** Output is always a NEW version of the master (`YYYYMMDD_AllMarkets-OffMarket-Master_v##.xlsx`); prior versions are never deleted.
7. **Assert SF meaning before use.** Any field feeding building SF must be proven to be BUILDING area, not land. Field labels lie (confirmed cases: Franklin OH `STATEDAREA` = sq ft despite an alias of "Legal Acres"; Jackson MO `total_sqft` = land; Marion IN `ESTSQFT` = lot). A SF field that ≈ parcel land area, or that equals the screen's own land column, is land — reject it.
8. **WAF-blocked exact-match filters — fall back client-side.** Some county ArcGIS/CAMA endpoints reject or silently empty-return `WHERE <field>=<value>` queries (WAF strips or 403s the `=` operator) while `IN (...)`, wildcard/`LIKE`, or an unfiltered paginated pull succeed against the same data. A zero-row or error response to an `=` filter against an endpoint known to hold the record is NOT proof of absence. On empty/error: retry as `IN ('value')`; if that also fails, pull the full/paginated table unfiltered and filter client-side post-fetch. Never record a parcel as unrecoverable off an `=`-filtered 403 alone.
9. **Multi-row owner/deed records — key on type, not order.** Deed and Mail-To tables frequently return >1 row per `parcel_id` (joint owners, trustee + trust, prior + current owner, deed history). Taking the first matching row is an arbitrary pick, not a resolved owner. Resolve on an explicit type/role/status field (`OwnerType`, `IsCurrent`, `Primary`, most-recent `DeedDate`) instead. If no such field exists in the source table, the parcel is NOT auto-resolvable — quarantine it (`NO-OWNER(ambiguous)`) for manual resolution rather than guessing.
10. **Assessed→Modeled-Market conversion is calibrated, never assumed (added v1.4, 2026-07-12).** A recovered value field's basis relative to true market value is NOT self-evident from a field name or a general statutory rule, even one already relied on elsewhere in this skill (MO commercial /0.32, KS commercial /0.25, "OH auditor values = 100% market"). Those defaults hold at the *state* level in aggregate but are not guaranteed at the *county* level once a county's recovery method changes (e.g., a different CAMA export, a redacted public-view service, an undocumented secondary values layer). Precedent: Clermont and Warren OH (2026-07-12) — 736 rows had real recovered SF and a real recovered value field, but no county-specific test confirmed that field was already at parity with true market value; Hamilton/Butler OH's own ratios did not hold as a clean fixed multiplier row-to-row, ruling out a blind carry-over of the "100% market" default to the two new counties. **Ratified resolution (Gabriel, 2026-07-12 — corrected v1.5; supersedes the sale-comp-sample plan below, which was never executed):** use the **ORA Replacement Cost Table (RCT) floor-discount** in preference to both a blind cross-county ratio and a fresh comp-sample pull. Check Year Built coverage first — a true cost approach (RCN less age-based depreciation) needs it. If coverage is too sparse to support depreciation (Clermont/Warren: 5/749 rows had Year Built), fall back to a flat vintage-floor discount off RCT LOW: `Modeled Mkt $ = Bldg SF × RCT_LOW × (1 − vintage floor)`. This sets Basis to 0 for every row by construction — an honest result, not a scoring defect (no evidence these parcels price below the conservative floor) — and must be tagged `[RCT-floor modeled valuation, not assessed-based]` in Verdict/P1 Note so it stays distinguishable from assessed-basis counties downstream. A sale-comp-sample calibration (**~15-20 parcels/county**, ratio = sale price ÷ recovered value field, median across the sample) remains an acceptable alternative when Gabriel prefers it or Year Built coverage is adequate for a true cost approach — but it is NOT the default; ask before running one instead of RCT-floor. Do NOT: (a) apply a statutory or "another county's" ratio uncalibrated, or (b) leave the rows in permanent DATA-GAP with no plan — either is a unilateral valuation call this skill does not have standing to make. If neither RCT-floor nor a comp-sample pull can be completed in the current pass, tag the county `DATA-GAP: methodology decided, calibration pending` (not `KILL`, not shipped, not silently reverted to a blind ratio) and name the row count blocked, so the gap has a visible size and owner rather than sitting open indefinitely.
11. **RCT version is imported, never embedded (added v1.6, 2026-07-27).** This skill does NOT carry its own copy of RCT $/SF figures or the vintage-floor ramp. Pull both, every run, from the authoritative sources: `acquisition-underwriting`'s "Replacement Cost Table (RCT v03)" section (canonical), cross-checked against `config/replacement-cost.v3.json` in oxford-command-center (`rctVersion: "replacement-cost.v3"`, ratified 2026-07-14 — if that file and the skill table ever disagree, the skill table wins and the file is the bug). Cite the exact RCT version string used on every screen. This rule exists because the pre-2026-07-27 version of this skill hardcoded RCT v02 figures (Columbus 124.86, KC 117.80, Cincinnati 121.61, etc.) and a simplified 25%/30% vintage cliff directly in its own text — both went stale silently when RCT v03 was ratified 2026-07-14 and nothing forced a resync. Any parcel scored under this skill's old embedded v02 numbers between 2026-07-14 and 2026-07-27 needs re-derivation (see changelog v1.7).

## Workflow

1. **Scope** — identify counties with `Bldg SF` and/or value blanks in the master (UNSCREENABLE / DATA-GAP verdicts).
2. **Probe** — verify endpoints in `references/endpoints.md` are live (county servers go down; UG WyCo was 521 at origin on 2026-06-11 — recheck `landsweb.wycokck.org` and `maps.wycokck.org` before any Wyandotte reprice). Confirm whether the endpoint accepts `=` filters before relying on empty results (Iron rule 8); note `IN`-only endpoints in `references/endpoints.md`.
3. **Recover** — batch ArcGIS REST queries (`WHERE <pin-field> IN (...)`, chunks of ~75) or bulk CAMA downloads per endpoints reference. Parallelize counties across subagents for large scopes. Write incremental CSVs (resumable): `sf_<Metro>_<County>.csv`, `values_<Metro>_<County>.csv` with columns `parcel_id` (EXACT input format), `bldg_sf`, `yr_built`, `land_use`, `mkt_lnd`, `mkt_imp`, `mkt_total`, `delq_taxes`, `method`, `source_url`.
4. **Sanity** — modeled $/SF medians must land ~$25–45/SF for shallow-bay in ORA markets. Median ~$10–15 ⇒ fractional assessed value; the MO /0.32, KS /0.25, and OH-100%-market defaults are STARTING hypotheses per Iron rule 10, not automatic conversions — confirm each county's basis against its own comp sample or against the RCT floor-discount method before applying, and never carry a ratio over from a different county on assumption alone. Document `value_basis` per county, including how it was confirmed (comp sample, RCT floor-discount, statutory + spot-check, or "unconfirmed — DATA-GAP per Iron rule 10"). Run the unit-assertion gate below (workflow step 7). The $/SF and FAR medians are the same instrument pointed at value and at area — both must pass before recompute.
5. **Recompute P1** (constants per Buy Box & Scorecard, RCT v03 — see Iron rule 11; do not hand-edit these numbers here, pull them live from `acquisition-underwriting` / `config/replacement-cost.v3.json` each run):
   - NOI = SF × rent × 0.95 × 0.96 − 0.15 × SF (placeholder rent grid; `rent-comp` retired 2026-08-05 — its "P2" successor never shipped)
   - Walk = NOI / 0.08 · YoC = NOI / modeled
   - Vintage floor = **linear ramp, 65% at ≤1995 → 60% at ≥2005** (−0.5%/yr; ratified 2026-07-14 — supersedes the old "0.25 if yr ≥ 2000 else 0.30" step function, which was calibrated against RCT v02's understated denominator and is no longer valid against v03). Unknown Yr Built defaults to 1995 (conservative, 65% required).
   - Disc = 1 − (modeled/SF)/RCT_LOW
   - Basis/25 = clip((Disc − floor)/(0.76 − floor) × 25) — top-of-scale recalibrated 2026-07-14 from ≥55% to ≥76% alongside the RCT v03 denominator; do not use 0.55, it predates the correction.
   - Yield/20 = clip((YoC − 0.08)/0.03 × 20)
   - Motiv/10 additive: estate +5, delinquency +4 (delq > $1,000), in-motion +3, absentee +2, non-arms +1, hold ≥ 15y +1, cap 10
   - VA/6: +2 if land SF / bldg SF ≥ 2.5 (only when acres present) · Mkt/12 per metro baseline
   - Gates: SF > 50K KILL (note aggregate-SF caveat for footprint sums) · modeled < $400K or > $12M KILL · MaxP/Modeled < 0.60 KILL basis-improbable; 0.60–1.0 CLEAR-AT-DISCOUNT (promotable); ≥ 1.0 CLEAR (promotable)
   - RCT LOW $/SF (v03, ratified 2026-07-14 — cite this version, not v02): Columbus 229.65 · Cincinnati 251.46 · Kansas City 227.90 · Indianapolis 253.83 · Mid-Atlantic/Baltimore 232.97 · Madison 229.08 `[PROXY]` · Grand Rapids 253.11 `[PROXY]` · Richmond 232.97 `[PROXY]` · Des Moines 231.66 `[PROXY]`. `[PROXY]` markets always trigger DENOMINATOR-SENSITIVE. Treat this list as a convenience cache only — if `acquisition-underwriting`'s own table shows a different number on the day of a run, that one governs and this list is stale.
6. **Rebuild** — regenerate master with provenance columns (`SF Source`, `Value Source`, `Delq Taxes`, `P1 Note`), re-rank Top 100 across metros (T2-QUEUE only, stale-value rows excluded), update Summary verdict counts, append README + QC provenance rows.
7. **QC gate** (all must pass before delivery): row counts preserved per tab; zero shipped-SF overwrites; Exclusions parcels absent from all tabs; Top 100 all-T2/no-stale/sorted; spot-check Basis/Yield/NOI math on ≥3 rows per metro; $/SF medians in range; delq Motiv within 0–10.

   **Unit-assertion gate** (run per county, before any FAR or economics ship):
   1. **bldg < land:** for ≥90% of rows, recovered `bldg_sf` < `land_sf`. A county where bldg ≥ land for a large share is using a land field as building SF — STOP, re-source.
   2. **Kill-gate consistency:** no parcel the screen KEPT may carry recovered "building SF" > 50,000 unless independently confirmed multi-building; >50K on a kept row is a land-field tell.
   3. **FAR-median band:** county median FAR must land ~0.10–0.50 (shallow-bay range). Median ≈ 1.0 ⇒ land-as-building (the Marion `ESTSQFT` signature); median < 0.03 ⇒ building-as-land or wrong join.
   4. **Source-field provenance:** every recovered SF carries the exact source field name + verified unit in its `method`/`source_url` tag (e.g. "FEMA SQFEET", "iasWorld AREA sum", "footprint Shape__Area sqft").
   5. **No reprojected areas:** take area from the authoritative source field; never recompute from Web Mercator geometry.

   Any sub-gate failure ⇒ that county's SF is quarantined (kept blank, tagged `NO-SF(recover)`), never shipped.

   **Filter/owner-resolution gate** (added v1.2, run alongside the unit-assertion gate):
   1. No row quarantined solely on an `=`-filter 403/empty-result without an `IN`/unfiltered retry per Iron rule 8.
   2. No owner/mail-to field populated from a multi-row match without an explicit type-field resolution (Iron rule 9); ambiguous multi-row parcels carry `NO-OWNER(ambiguous)`, never a silent first-match value.
8. **Deliver** — present workbook; mirror to SharePoint `Investment Candidates -- 2026` when write access exists; route summaries to ggoldberg@oxfordra.net ONLY (routing canon 2026-06-10).
