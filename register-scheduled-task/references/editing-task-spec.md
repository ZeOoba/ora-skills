# Editing a task's SKILL.md content — full procedure

Moved verbatim from `SKILL.md` (v2.30 core/reference split, no rule changed). `SKILL.md` names every obligation in a one-line stub; this file holds the full wording. Read the relevant section BEFORE acting.

## Procedure

UPDATE above covers the registry (cron, enabled, prompt). This section covers the other half: changing the **instructions a task runs by**. Every ORA scheduled task's SKILL.md exists in two places — the fleet store the scheduler actually reads at fire time (`~\.claude\scheduled-tasks\<id>\SKILL.md` for CC/MCP; `OneDrive…\Documents\Claude\Scheduled\<id>\` for LAMS), and the git-tracked copy under `~/.claude`. The registry stores only a `filePath`, so **committing an edit changes nothing about what runs** — the same trap as "a merged PR is not a live deploy" in `CLAUDE.md`'s Release rule. Never report a content fix as done on the strength of a commit.

Procedure, in this order:

1. **Edit in a worktree, never the shared checkout.** `~/.claude` routinely carries 100+ dirty files from concurrent sessions; editing there co-mingles hunks. Gate with `preflight-shared-checkout.py` before committing, passing the sha you actually built on — a stale `--since` returns `HEAD_MOVED`, which reads identically to real contention (`memory/feedback_preflight_stale_since_false_contention.md`). Check `dirty_overlap_foreign` and `competing_claims` in its `RESULT_JSON` before believing a contention verdict.
2. **Make the edit with the Edit/Write tool, not a Bash heredoc/sed/script.** Provenance is recorded only by the Edit/Write hook, so a Bash-written file reads to the gate as having no owner and returns `CONTESTED` against your own work (`memory/feedback_preflight_provenance_needs_edit_tool.md`). Re-applying the identical edit through Edit is the fix; `--force` never is.
3. **Fix every site of the rule you are changing.** A skip rule, routing constant or threshold is typically stated in both a standing-prohibition section and the step that evaluates it. Changing one leaves the spec self-contradictory and an agent free to follow either. Grep the file for the constant before editing, and quote every site back when reporting.
4. **Back up the live file, then propagate.** Copy the live SKILL.md to `SKILL.md.bak-YYYY-MM-DD-<reason>` beside it (`.bak` is gitignored under `scheduled-tasks/`) — Hard Invariant 6, never overwrite a config without reading it first. Then copy the committed version over the live path.
5. **Check line endings BEFORE the copy.** Live files are a CRLF/LF mix (check per file), and `core.autocrlf=true` checks the worktree out as CRLF regardless. Write each file in the LIVE file's own style; a style flip rewrites every line and destroys any ability to diff the real change. Confirm `diff --strip-trailing-cr` shows only the lines you meant to touch. `~/.claude/maintenance/propagate-task-spec.py` does steps 4–6 (dry-run default; refuses mixed EOL, stale backups, unplanned diffs, uncommitted sources; rolls back failed writes).
6. **Hash-verify.** For CC files, `git hash-object --path <repo path> <live file>` must equal the committed blob — a raw `sha256sum` against `git show` output reports false drift, because git stores LF. For LAMS (not in git), raw sha256 of live vs the edited copy. A copy that silently failed looks exactly like a copy that worked.
7. **Test the changed rule against real data before declaring done.** If the edit changed a matching rule, run it over the actual population it will face plus adversarial cases — for a name-based skip rule, every real counterparty name in that pipeline (must NOT match) and every sentinel variant (must match). Doctrine asserted is not doctrine verified; this is the Done-bar's evidence-before-claim applied to prose specs.

**Do not silently widen a matching rule to make it simpler.** A skip/exclusion pattern must stay anchored and narrow enough that it cannot swallow real counterparty work: a false negative on a genuine tenant, deal or payment is far worse than the false positive the rule exists to stop. Record that reasoning inline next to the rule, so a later "tidy-up" does not undo it. The test-artifact convention is the `ZZ` sentinel — `^ZZ[\s._-]*TEST`, case-insensitive, leading whitespace stripped, anchored prefix only (never a bare `TEST`, which matches real tenants like "TESTA Construction"). Use that same sentinel for any new name-based test exclusion rather than inventing a per-task variant.

**The same live-vs-source split exists for SKILLS, and is not this skill's to fix.** `~/.claude/skills/synced/<uuid>/<skill>/SKILL.md` is what Claude loads; `C:\Users\Owner\ora-skills\<skill>\SKILL.md` is the source of record. They drift (measured 2026-09-19: this skill was v2.21/120 lines live against v2.24/141 lines in source). Before quoting a skill's own doctrine at someone, check which copy you read.
