# register-scheduled-task — changelog v2.17–v2.20 (full text of entries compressed out of SKILL.md)

- **v2.17 (2026-08-24, Gabriel-ratified):** Added the **ONE-TIME EFFICACY-CHECK CHECK** to the Bounded pause section, and a matching QC-gate item — closing the doctrine gap left open at v2.12 and flagged as "his call" in the 2026-08-21 pm-ledger efficacy report (question 2). The RESUME-TIME COLLISION CHECK (v2.15) protects a *paused* task's own recurring slot; it says nothing about a separate one-time (`fireAt`) task whose *measurement window* merely overlaps someone else's pause. Root incident: the 2026-08-17→08-21 pause silently voided `ora-pm-ledger`'s 08-12-armed retime check and `ora-psa-drift-watch`'s same-afternoon check — both read the send log over a window the pause fell inside, both reported false misses (`memory/reference_bounded_pause_voided_overlapping_efficacy_checks_2026-08-21.md`). The fix is procedural, mirroring v2.13's progress-marker lesson (a bare reminder wasn't enough; it has to be an enumerate-and-decide step): before committing any bounded pause, list every one-time task on the affected fleet(s) whose `fireAt` falls inside the pause window, and for each one that measures delivery/status over that window, either defer its `fireAt` past the resume or explicitly record it as knowingly-voided in the same pass. Doc change only — no script changes.
