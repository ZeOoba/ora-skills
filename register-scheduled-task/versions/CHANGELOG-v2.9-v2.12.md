# register-scheduled-task — Changelog (v2.9–v2.12)

Archived from `SKILL.md` 2026-08-22 (ORA Automation Audit Revision 18 remediation — repo-only, excluded from packaging per `tools/package_skills.py`'s top-level `versions/` exclusion). Current version's changelog entry lives in `SKILL.md` itself; only superseded entries move here going forward. Continues `CHANGELOG-v2.0-v2.8.md`.

- **v2.12 (2026-08-17):** Added "Bounded pause — the resume is part of the pause, not a follow-up." A pause with a stated end must register its resume in the same supervised session/surface/pass, per fleet; "pause all routines" is fleet-ambiguous and must be resolved against both registries before acting; the heartbeat/health-monitor detectors must not be swept into a blanket pause without saying so; and a resume must NOT re-stamp `[MODEL:]` dates (which qualifies v2.8's re-enable re-tag rule — that binds a hand re-enable, not an automated bulk resume). Root incident: a 2026-08-17 "pause all routines until Friday 5pm" was executed on CC/MCP with a resume registered (`ora-routine-pause-resume-08-21`, fires 2026-08-21 17:00 ET), while the LAMS/Cowork counterpart pause landed with NO resume — verified same day: 35/40 CC tasks disabled with a resume pending, 27/28 LAMS tasks disabled with none, including `ora-cowork-heartbeat` and `automation-health-monitor` themselves. Doc-only; no registration, cron, or archive-first-delete-second logic changed.
- **v2.11 (2026-08-17):** Added a RETIRE bullet — id-collision fleet-resolution must never be verified by deleting a live task. `delete_scheduled_task` has no fleet parameter and resolves by session locality; the only safe checks are `list_scheduled_tasks`' `path` field or the host surface's own reported client identity. Explicitly bars using `ora-cowork-heartbeat` or any dead-man/heartbeat id as a resolution test target. Root incident: a session retiring the `ora-passed-deal-tracker` LAMS duplicate had no documented safe way to confirm which fleet its `delete_scheduled_task` call would hit, and correctly declined to test against the heartbeat task to find out. Doc-only; no procedure/behavior change to registration, pause, or the archive-first-delete-second ordering.
- **v2.10 (2026-08-17):** Added a surface note to the Dual-fleet registry model section — cloud-sandbox Cowork sessions (device-bridge only, no native app process) never carry the `create_scheduled_task`/`update_scheduled_task`/`delete_scheduled_task`/`list_scheduled_tasks` MCP tools; only a session running natively on-device does. Root incident: an `ora-passed-deal-tracker` LAMS id-collision deregistration was dispatched to a cloud Cowork session, and the tool gap was discovered mid-task (correctly stopped per Rule 1) rather than routed to a native on-device session from the start. Doc-only; no procedure/behavior change.
- **v2.9 (2026-08-15):** Added step 4c — a post-registration fire-time sanity check comparing `nextRunAt` against the stated cadence's expected interval, flagging same-turn when a task registers after its own slot already passed for the cycle (silently waits a full cycle otherwise). Root incident: `ora-psa-drift-watch`, registered 2026-08-12 after a delayed permission request pushed it past that day's 1:30 PM Wednesday slot — it sat silent until the following Wednesday with nothing catching the wait at registration time.
