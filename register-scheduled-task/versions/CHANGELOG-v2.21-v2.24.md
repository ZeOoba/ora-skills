# register-scheduled-task — Changelog v2.21–v2.24 (full text)

Entries compressed out of `SKILL.md` under the 6-entry retention rule. Open range: later compressions (v2.22–v2.24) append here.

- **v2.21 (2026-09-07):** Added step 3c — CLAIM-BEARING TASKS must claim under the `sched-` namespace (`sched-<slug>`, hyphen not colon), never the bare slug, when the task's own instructions call `hooks/lib/claim_work.py claim`. This is the carrier for the 2026-09-07 Gabriel ruling (`memory/tech.md` §3e, closing OI-116): the namespace existed in `claim_work.py` alone, but no scheduled task's instructions actually claimed under it, so the shorter 30-minute TTL and the "force-takeover is ROUTINE" refusal never reached a live unattended holder — the exact OI-116 failure mode (an unattended holder that cannot be messaged and self-renews). QC gate gained the matching item. Five full inline entries after this edit — one below the retention cap. Doc-only; no registration/pause/retire procedure changed.
- **v2.22 (2026-09-12, Gabriel-directed):** Added **RECORD THE PAUSE WINDOW** to the Bounded pause section, plus a matching QC-gate item. `fleet_pause.py` only answers "paused now", so once a resume fires the window is gone. The only past-pause record, a hand-written `*_FleetPause_RestoreLedger*.json`, existed for 08-17 and not for 09-07. The first `ora-health-guard` run after the 09-07→09-11 pause therefore reported 5 FAILs, 3 of them the pause itself. The new `maintenance/_shared/pause_windows.py` records per-task *held* intervals (disabled AND named by a pending resume) from observed registry state, durably. Two same-day adversarial refute passes killed the earlier SKILL.md-text-parsing design (10 false-negative paths, all "text is not state"). `pause-resume-guard.py` (native, runs every 6h) observes on every run as the backstop. `health-guard-beacon.py` (new `PAUSE_EXPLAINED` verdict) and `fleet-status.py` (a `pause-explained (NOT missed)` line) subtract the paused hours. This skill's part is doc-only: one capture+list step and one QC item.
